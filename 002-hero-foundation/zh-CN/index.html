01

Foundation 边界

Hero Canon 002 是推导 HeroOS 的理论 Foundation。它定义有 Accountability 的 Value Creation 所需的命题、关系、边界、反方观点与检验方式。

它不是正式的 HeroOS Specification。Canon 006 将规定 HeroOS 如何运作，包括角色、权限、记录、状态、工作流、接口、Control 与 Conformance Requirement。

02

目标读者

Hero Foundation 面向创始人、CEO、产品与工程负责人、架构师、领域专家，以及所有需要在丰裕智能时代设计价值创造系统的人。

03

基础论点

Hero 始于一种稀缺性的转移：当智能与执行能力变得更容易获得和组合时，人的可问责判断不会变得更不重要，反而会变得更重要。

这套理论必须解释：为什么仍然需要一个可识别的人类中心；组合能力如何放大这个人；价值如何通过证据与后果变得可检验；执行又如何转化为组织学习。

04

如何阅读本 Foundation

每个主要章节都必须完成五项论证责任：

  1. 定义：究竟提出了什么主张？

1. 基础问题

核心观点当能力变得丰裕，组织的基础问题会从“谁能执行”转向“谁对价值承担 Accountability”。

章节目的

确定 Canon 002 必须回答的问题，并把它与技术预测、管理潮流或道德口号区分开。

理论正文

在组织历史的大部分时间里，Execution Capacity 一直是主要组织约束。专业知识存在于人身上，软件的建设和修改成本很高，协作依赖反复的人际交接，获得专业能力通常需要招聘、层级或采购。在这些条件下，组织围绕获取劳动力、分配任务、监督工作和提高吞吐量进行设计，是合理的。

当这一假设不再足以解释现实，Hero 就开始成立。

某些由智能增强的 Execution，其成本与可获得性正在快速变化。一个人现在可以调用 Model、Software Service、Platform、Workflow 与远程专家，完成 Research、Analysis、Writing、Design、Coding、Monitoring 与 Coordination 的一部分。这不表示智能已经无限、平均分布、可靠或免费。它改变的是：一个人在不先扩张传统团队的情况下，可以尝试多少种行动。

当可以执行的选项增加，Execution 本身就不再足以决定组织能否创造 Value。组织仍然必须判断：什么问题重要，谁的利益应被计算，什么风险可以接受，哪些 Capability 值得信任，什么 Evidence 会改变判断，以及谁必须为结果作出回答。更多可执行行动可能提高错误选择的成本，也可能让薄弱假设、隐藏偏见与无人承担的 Consequence 更快扩张。

因此，Hero 的基础分析单位不是 Task、Prompt、Agent、Team 或 Output，而是 Value Commitment：一个可识别的人，在明确边界内，对追求特定 Value 作出 accountable promise，并评估其 Outcome 与 Consequence。

这会改变人的重要位置。人的价值不依赖亲自执行每个步骤，而在于 Purpose、合法解释、负责任的 Judgment、对 Capability Composition 的 Governance，以及对 Material Consequence 的最终回答。Hero 可以被大量人类与非人类 Execution 围绕，但 Value Commitment 不能失去承担者。

之所以需要人类中心，不是因为人的判断总是正确，而是因为 Value 存在争议，权衡会影响不同的人，而且系统在不确定条件下行动时，责任必须可以归属。NIST AI Risk Management Framework 同样把 Governance 视为跨周期能力，并强调 Human Centricity、Social Responsibility、Sustainability、Context，以及不同 AI Actor 对预期和非预期影响的责任。[S5] Hero 在此基础上进一步主张：每项 Value Commitment 必须保留一个具名的 Primary Accountability 中心。

推导

基础论证可以表达为：

  1. 在越来越多领域，由智能增强的 Execution 变得更容易获得与组合。
  2. 更大的 Execution Capacity 会增加可采取行动的数量与速度。
  3. 可以行动，并不能决定什么是合法 Value。
  4. Value 需要解释、权衡、Evidence 与对 Material Consequence 的接受。
  5. 这些判断需要一个可识别的 Accountability 中心。
  6. 因此，Execution 越丰裕，人的 accountable judgment 越重要，而不是越不重要。

这是一套关于组织约束的理论，不是关于人类永远正确的主张。Hero 对明确范围内的负责任判断承担 Accountability，而不是保证成功或无所不能。

必须建立的主张

  • Hero 是对智能经济性与可获得性发生变化的回应。
  • 分析的核心单位是 accountable value creation，而不只是任务完成。
  • 人的重要位置从独占执行转向目的、判断、Accountability 与后果。

必须完成的论证

  • 将“丰裕智能”定义为可获得性与可组合性的提高，而不是无限或免费的智能。
  • 说明为什么更多执行能力不会自动产生更多价值。
  • 解释为什么在模糊性与利益冲突中，价值创造需要一个承担 Accountability 的中心。

必须回应的反例

一个高度自动化的系统，可能看起来无需某个人逐项决策，也能持续产生有用结果。

边界

理论并不主张每一次具体执行都需要人同步介入。

可证伪检验

如果非人系统可以在不归属于任何人或人类制度的情况下，持续、正当地承担重大后果的 Accountability，这一主张就必须被削弱或修正。

2. 丰裕智能时代

核心观点丰裕意味着能力日益可获得、可复用、可组合，而不是稀缺已经消失。

章节目的

把 Hero 的环境前提定义得足够清晰，使其能够被挑战和检验。

理论正文

Hero 所说的“丰裕”是相对且可操作的概念。它意味着某类有用的 Intelligence 或 Execution 变得更容易获得、调用成本更低、复用速度更快，也更适合被组合。它并不表示所有 Capability 都已经可用、质量已经得到保证，或边际成本已经归零。

这个区别很重要，因为“智能”一词经常混合了四件不同的事：

  • Intelligence：在某个领域进行解释、推理、生成或决策的能力；
  • Capability：在明确条件下，反复产生可验证结果的能力；
  • Execution Capacity：合格 Capability 可以被执行的数量、速度与并发程度；
  • Outcome：在现实世界中产生的变化，必须根据 Value 接受评估。

Inference Cost 下降，是智能获取经济性改变的 Evidence，而不是 Value 已经实现的证明。Stanford 2025 AI Index 报告显示：达到 GPT-3.5 同等 MMLU 表现的模型，其调用成本从 2022 年 11 月每百万 Token 20 美元，下降到 2024 年 10 月的 0.07 美元，降幅超过 280 倍。[S1] 这说明某些机器智能更容易借用，但不能证明被借用的 Capability 适合具体 Context、组织能够完成集成，或最终 Outcome 有益。

现实生产率 Evidence 具有明显差异。NBER 对 5,179 名客户支持人员的研究发现，使用生成式 AI Assistant 后，每小时解决问题数量平均提高 14%；新手和较低技能人员提高 34%，但对经验丰富和高技能人员的影响很小。[S2] 同一类工具对 Execution Capacity 的影响，会随人员经验和任务 Context 变化。

反向 Evidence 同样重要。METR 在 2025 年初的随机研究发现：经验丰富的开源开发者在自己熟悉的 Repository 中使用 AI 工具时，完成任务反而多花费 19% 的时间。[S3] METR 明确反对把这一结果推广到大多数软件开发。其 2026 年 Follow-up 又指出，更广泛的 AI Adoption 与 Selection Effect 使后续估计不可靠；研究人员认为 Speedup 很可能已经增加，但其幅度只有薄弱 Evidence。[S4]

这些研究既不支持“普遍丰裕”，也不支持“普遍无效”。它们支持一种与 Context 相关的转变：访问成本和机器 Capability 可以快速改善，而实际 Execution 收益仍取决于经验、任务结构、隐含要求、质量门槛、集成实践与时间。

丰裕指标

当以下多个指标共同改善时，一个领域才是在走向 Execution 丰裕：

  • 获得明确 Capability 的成本下降；
  • 从 Intent 到合格 Execution 的等待时间下降；
  • Capability 可以跨 Commitment 复用，而不需要大量重新建设；
  • 多个 Capability Unit 可以组合，且不会产生不成比例的 Coordination Cost；
  • Qualification 与 Evidence 能够跟上 Execution 扩张；
  • 组织可以增加 Execution Capacity，而不需要同比例增加 Headcount。

任何单一指标都不充分。廉价但不合格的 Output 不是丰裕 Capability；快速但不可观察的 Execution 不是可治理的 Scale；脱离 Context 的 Benchmark Performance 不是可靠组织能力。

不均匀的丰裕

丰裕智能时代不会同时到达所有领域。Digital Knowledge Work 的访问成本可能下降，但 Physical Work 仍受到设备、能源、材料、地点、安全和人在现场的限制。一项决策在技术上可以执行，却可能在法律上不可委托。高度依赖关系的决策可能需要无法由输出质量替代的信任。组织即使能够访问强大 Model，也可能缺少干净数据、Permission、Integration 或 Governance。

因此，Abundance 是某个 Capability 在特定 Context 与特定时间中的属性，不能仅根据某项技术已经存在就作出判断。

必须建立的主张

  • 在许多知识工作领域，智能驱动的执行正在变得更便宜、更易获得。
  • 软件、AI、平台、服务与专业人员，越来越能够作为 Capability Unit。
  • 丰裕在不同领域、地区、组织与物理约束下并不均匀。

必须完成的论证

  • 区分 Intelligence、Capability、Execution Capacity 与成功结果。
  • 提出可观察的丰裕指标，例如获得成本、响应时间、复用程度与组合速度。
  • 解释为什么物理型、强监管、安全关键与高度依赖关系的领域仍可能受执行稀缺约束。

必须回应的反例

在物理运营中，稀缺设备、材料、许可或熟练劳动力仍可能是真正瓶颈。

边界

Hero 不主张 Execution 永远不再是瓶颈。它主张相对稀缺结构正在改变，而且必须按领域验证。

已确认的 Scarcity-Shift Hypothesis

“Execution is no longer the bottleneck” 继续作为 Manifesto 语言成立。Canon 002 使用有边界的理论主张：

Execution 不再是普遍或默认的瓶颈。在越来越多由智能增强的工作中，真正形成约束的稀缺性，正在转向 Value 判断、Accountability、治理、Evidence 与 Consequence。

当所需 Capability 可以获得、组合、得到充分 Qualification 并可验证，Execution 成本或等待时间持续下降，必要数据、工具与访问权限存在，而且物理、法律、安全或关系约束没有继续占据主导时，该假设成立。

在物理生产、现场服务、稀缺设备或劳动力、安全关键与强监管工作、高度依赖信任的工作、尚未形成可复用 Capability 的探索性工作，以及缺少数据、权限或基础设施的组织中，Execution 仍可能是主要瓶颈。

对于一项 Value Commitment，实际检验问题是：

如果合格 Execution Capacity 增加一倍，预期 Outcome 是否会显著改善？

如果会，Execution 仍可能是关键约束。如果不会，约束可能来自 Value 不清晰、Authority 不足、Accountability 模糊、Capability 无法治理、Evidence 薄弱或 Judgment 延迟。

Scarcity-Shift Hypothesis 主张：随着可获得、可组合的执行能力扩张，组织约束将逐渐从“工作能否执行”转向“什么值得执行、谁接受 Accountability，以及如何判断结果”。

可证伪检验

如果在 Hero 所适用的大多数领域中，执行能力仍长期是主导约束，那么这一广义主张必须缩小适用范围。

07

3. 稀缺性转移：从执行到 Accountability

核心观点随着执行能力扩张，稀缺能力转向对价值与后果作出可问责判断。

章节目的

推导“Accountability is the new scarcity”，而不是只把它作为宣言使用。

理论正文

当一种约束的扩张速度超过另一种约束时，稀缺性就会转移。如果合格 Execution 越来越容易获得，但合法 Judgment、明确 Commitment、Governance 与 Consequence Ownership 的能力没有同步增长，Accountability 就会成为真正限制组织的约束。

这不意味着更少的人需要负责，而是 Execution 被委托得越多，组织越需要知道最终回答关系位于哪里。一个 Hero 可以使用许多 Capability Unit，许多人也可以承担 Responsibility 或 Independent Accountability。真正的问题出现于系统已经可以行动，却无法清晰回答四个问题时：

  1. 这项行动准备创造什么 Value？
  2. 谁拥有作出重大 Judgment 的 Authority？
  3. 什么 Evidence 可以确认或挑战该决定？
  4. 谁必须解释并响应其 Consequence？

技术不会因为产生更多 Output 就自动回答这些问题。事实上，Execution Capacity 越大，问题可能越困难，因为更多行动可以在影响被理解之前被启动、组合与重复。NIST AI RMF 把 Governance 描述为 Cross-cutting Function，并指出 AI Lifecycle 中不同 Actor 可能拥有不同的风险视角和责任。[S5] Hero 接受这种责任多元性，但拒绝因为责任多元，就让 Value Commitment 变得无人承担。

Responsibility 与 Accountability

Responsibility 与 Accountability 相互关联，但不能相互替代。

Responsibility 是采取行动、执行、支持、审查或确保工作发生的义务。复杂工作需要许多贡献者和 Control，因此 Responsibility 可以被拆分。

Accountability 是在明确范围内，对 Judgment、Value 与 Material Consequence 作出最终回答的关系。它必须保持可识别，因为 Execution Delegation 无法回答：为什么接受这项 Value Commitment，如何解释相互冲突的 Evidence，以及为什么接受某项风险。

“不可转移”不表示一个人吸收所有法律、道德、专业或运营责任。它表示 Execution 不能被用来消解附着于 Value Commitment 的 Primary Accountability。在安全、合规、专业完整性或制度边界需要独立 Judgment 时，Independent Accountability 仍然必要。

为什么 Accountability 会变得稀缺

Execution 往往可以通过资本、软件、平台、外部服务或增加 Capability Unit 被复制。Accountable Judgment 更难扩张，因为它需要 Context、合法 Authority、注意力、解释能力，以及接受 Material Consequence 的意愿。

真正稀缺的不是愿意获得某个头衔的人数，而是这样的能力：作出明确 Commitment、保留足够 Context、抵抗误导性 Output、响应 Counterevidence，并在 Outcome 不确定或不利时继续作出回答。

Hero 组织不会通过把所有人都称为 Accountable 来解决这种稀缺。没有区分的 Shared Accountability 会让 Judgment 的位置变得更不清楚。系统必须区分 Primary Accountability、Distributed Responsibility、Independent Accountability 与 Institutional Accountability。

集体结构

董事会、委员会、合伙关系与法人可以拥有真实的制度 Authority 与 Responsibility。Hero 不否认 Collective Governance，而是要求集体结构保留可识别的 Decision Right 与人类 Role-holder。

委员会可以共同讨论，但其 Mandate 必须说明：决定如何获得授权、治理哪项 Value Commitment、如何处理分歧与冲突，以及谁必须确保 Evidence 与 Consequence 获得响应。一个机构可以继续承担法律 Accountability，同时由一名具名 Hero 对具体 Value Commitment 承担 Primary Accountability。只要范围明确，这些层次可以并存。

真正的选择不是 Collective Governance 与个人英雄主义之间的选择，而是 Accountable Collective Governance 与责任消失在角色之间的结构之间的选择。

必须建立的主张

  • 委托执行并不等于委托最终的 answerability。
  • 可选行动越多，对选择、解释与后果承担的需求越高。
  • Accountability 不能仅由头衔、权力或与执行的距离推断。

必须完成的论证

  • 用真实组织结构检验已经确认的 Responsibility 与 Accountability 区分。
  • 定义在明确范围内，什么使 Accountability 可识别且不可转移。
  • 回应个人、共同、制度、法律与道德 Accountability 的不同形式。

已确认的塑形基线

Responsibility 是采取行动、履行职责或确保明确工作得以发生的义务。Responsibility 可以被分配、委托或共同承担。

Accountability 是在明确范围内，对判断、价值与重大后果作出最终回答的关系。Execution 可以委托，但 Accountability 不得因委托而消失。

每个 Value Commitment 都必须存在一个可识别的 Primary Accountability 中心，即一名明确的人类 Hero。这并不意味着其他 Accountability 会消失。

  • Distributed Responsibility 可以分配给人员、团队与 Capability Unit。
  • Independent Accountability 可以由其他人针对安全、风险、合规、专业或制度约束独立承担。
  • Institutional Accountability 可以由组织在法律或治理层面承担，但必须通过明确角色和可识别的人类角色承担者实现。
  • Shared Accountability 只有在责任范围、决策权与冲突解决机制都被明确时才成立。Hero 不接受“所有人共同负责，但无人最终回答”的模糊共同 Accountability。

必须回应的反例

董事会、合伙关系、委员会与法人经常承担集体或制度性 Accountability。

边界

一个 Primary Accountability 中心并不意味着单方面权力、无限责任、无所不知或取消独立治理。它意味着 Value Commitment 在集体结构中不能失去可识别的人类最终回答关系。

Accountability 受到已接受的 Value Commitment、合法决策权、合理可预见性、实际控制或影响能力，以及明确评估周期的限制。但这些边界不允许 Hero 在明知缺少必要 Authority 的情况下接受 Commitment。

可证伪检验

如果 Accountability 可以被彻底分割，以至于不再需要任何可识别的人对判断与重大后果负责，那么“不可转移”主张就必须修正。

4. 价值的人类中心

核心观点Value Commitment 需要一个可识别的人类中心，因为价值在被创造之前，必须先被解释。

章节目的

解释人的首要地位，但不声称人必须执行每项任务，也不声称人在每项执行中都更优秀。

理论正文

Value 既不始于生产，也不始于衡量。它始于有人把“值得追求的改善”与“仅仅可能发生的变化”区分开来。Output 描述产生了什么；Efficiency 描述投入与产出之间的关系；Revenue 记录一次交换；Preference 记录一个主体声称或通过行为表现出的愿望。它们都可以成为 Value 的 Evidence，但没有任何一项单独足够。一个系统可以高效地产生无人需要的输出，可以通过把伤害转移给其他人而获得收入，也可以满足受益者的即时偏好，却损害其长期利益。

因此，Value 同时是一项规范性判断和经验性判断。它具有规范性，是因为必须选择 Purpose、Beneficiary，以及可以接受的 Consequence 分配；它具有经验性，是因为所宣称的改善及其后果必须持续接受 Evidence 的检验。Hero 因而拒绝两种简化：Value 不是决策者个人偏好的任何事物，也不是某项指标能够优化的任何事物。个人偏好并不天然拥有支配所有受影响者的合法 Authority；优化指标则会继承其目标函数中被遗漏的内容、时间跨度与 Stakeholder 假设。

Value 的人类中心，是这些假设最终必须得到回答的位置。这个人不必亲自执行工作、计算最优解或批准每个局部决定。这个中心是人类 Primary Accountability 所在，它必须能够解释：为什么某个 Beneficiary 是合法的，为什么这项改善值得追求，考虑了哪些相互竞争的利益，接受了哪些 Consequence，以及什么情况会导致 Commitment 被修订或停止。制度可以通过法律、使命、受托义务、专业标准、民主授权或治理结构，授权并约束这种判断。这些制度扩展了人类判断的合法性，但不会取消在具体 Value Commitment 中识别一个人类中心的必要性。

受益对象与合法性

合法 Beneficiary 可以是人、组织或社会。这三类并不相互排斥，也不意味着利益必然相等。一个产品可能同时创造客户效用、员工机会、组织收入、供应商需求与公共税收，也可能产生环境成本。因此，多类受益对象的存在并不能直接证明整体结果是合法的，而是产生了一个 Judgment 问题。

合法性通过四个相互连接的问题建立：

  1. Purpose：这项改善是否与 Value Creation System 获得授权的 Purpose 相关？
  2. Standing：哪些人、组织或公共利益受到重大影响，因此有资格被纳入考虑？
  3. Boundaries：哪些法律、宪法、合同、伦理、专业或制度边界约束这项选择？
  4. Consequence：重大收益、负担、风险、可逆性与时间跨度是否被清楚呈现，而不是被排除在 Value 声明之外？

这些问题不会自动产生公式，而是约束 Judgment。Stakeholder 的利益经常发生冲突；宣布每个 Stakeholder 都重要，并不会让冲突消失。例如，Business Roundtable 的公司 Purpose 声明同时承诺客户、员工、供应商、社区与股东的长期价值。它说明商业 Value 可以明确包含多类 Stakeholder，同时保留经济价值要求；但它没有证明这些利益天然一致，也没有提供解决所有权衡的方法。[S6]

当利益发生冲突时，Hero 不能把冲突隐藏在一个综合分数之中。Hero 应明确：谁的状态预期得到改善，谁的状态可能恶化，哪些约束不可交易，接受了怎样的分配，以及哪些 Evidence 会要求重新判断。即使某个方案在技术上更优，如果目标函数排除了具有 Standing 的主体，把受保护的边界当作可交换变量，或把重大 Consequence 外部化到评估时间跨度之外，它仍可能不合法。

经济可持续性

经济可持续性不等于短期利润，但对商业系统也不是可选项。一项 Commitment 可以通过 Create、Protect、Enable 或 Consume Justifiably 创造 Value。这四条路径避免把每个局部行动都包装成虚假的直接收入声明，同时仍要求解释资源使用。员工安全、监管合规、基础设施、Capability 建设以及履行正当社会义务，可能消耗资源而不立即产生利润；只要其 Purpose、Consequence 与经济关系明确，它们仍然可以是 Value。

然而，在完整的商业 Value Creation System 层面，Commitment 的整体组合必须在相关时间跨度内保持可信的利润路径。缺少这一路径，组织最终会失去继续服务任何 Beneficiary 的能力。在公共或社会系统中，对应要求是可持续治理：资源、Authority、制度信任与运行能力不能在缺乏合理更新或优先级依据的情况下被持续消耗。因此，可持续性是 Value 的边界，而不是 Value 的唯一含义。

当不存在一个能够合法吸收上述所有问题的稳定目标函数时，人的首要地位最为重要。一旦合法目标、运行边界与 Escalation Rule 已经建立，机器完全可能比人更擅长计算、搜索、预测或执行。Hero 并不把 Execution 保留给人，而是把对 Value 的可问责解释以及对 Consequence 的接受，保留在人或由人授权的制度秩序之中。

必须建立的主张

  • 价值不等于输出、偏好满足、收入或效率。
  • 价值取决于目的、利益相关者、权衡、时间跨度与被接受的后果。
  • Hero 是这些解释最终变得可问责的人类位置。

必须完成的论证

  • 定义人在模糊条件下进行判断的作用。
  • 检验利益相关者发生冲突时，合法 Value 如何被建立。
  • 说明正当性与技术优化之间的区别。

已确认的塑形基线

Value 是对合法受益对象产生的实质性改善。受益对象可以是人、组织或社会。该改善必须可以被识别、能够通过 Evidence 接受评估、与其重大 Consequence 一并考虑，并具有可持续的经济或资源基础。

Value 的合法性来自相关 Purpose、受影响的 Stakeholder，以及制度或宪法性边界。Hero 负责解释、权衡并接受 Value Commitment 的 Accountability，但不能依据个人偏好单方面发明什么算作 Value。

对于商业组织，每项 Value Commitment 不一定直接产生利润，但必须通过以下至少一条路径说明它与经济价值的关系：

  • Create：增加收入、利润率或利润。
  • Protect：减少损失、风险、责任或经营合法性的丧失。
  • Enable：建立未来创造价值与利润所需的 Capability、资产、知识或选择权。
  • Consume Justifiably：为正当的人类、社会、法律或制度义务使用经济资源。

在完整的商业 Value Creation System 层面，经济可持续性以及可信的利润路径仍然是必要条件。在公共或社会系统中，对应约束是对财政、制度及其他稀缺资源的可持续治理。

必须回应的反例

当目标函数稳定且已被接受时，优化系统可能比人类决策者表现更好。

边界

人的首要地位适用于对价值的解释与后果承担，不意味着人在每个任务中的执行质量都更高。

可证伪检验

如果存在争议的价值可以在没有任何人类判断或人类授权制度的情况下，被正当地定义与修订，该主张就不成立。

5. Capability 理论

核心观点Capability 是在明确条件下，能够反复产生可验证结果的能力。

章节目的

建立一个理论单位，使人、软件、服务、平台、workflow 与 AI 的执行能力可以被比较，同时不把它们视为相同事物。

理论正文

Capability 是在明确条件下，能够反复产生可验证结果的能力。它是一种能力，而不是拥有它的主体；是一类结果，而不是一次输出；是一项经过资格确认的依赖声明，而不是对潜力的描述。因此，说某个人、模型、服务或平台“能够”做某件事，弱于说该 Capability 可以被负责任地用于一项 Value Commitment。

五个要素使这项依赖声明具有意义：

  • Result：确定 Capability 预期产生的结果类别，包括相关质量与 Consequence 边界；
  • Repeatability：意味着在一类有意义的场景中可以依赖该结果，而不是每次 Execution 都使用完全相同的步骤或产生完全相同的内容；
  • Verification：提供区分可接受结果与貌似可信 Failure 的方法；
  • Operating Conditions：说明依赖声明成立的 Context，包括输入、环境、Authority、Dependency、Scale、时间及重大假设；
  • Qualification：基于 Evidence 作出的 Judgment，即某个具体 Capability Unit 适合在预期用途下提供该 Capability。

这一定义把 Capability 与相近概念区分开来。一个人或工具可以拥有多项 Capability；Task 是一次工作实例，可能需要多项 Capability；Role 聚合预期的 Accountability 与 Responsibility；Output 是一次产生的 Artifact 或 Action。Capability Unit 是经过资格确认、能够在指定条件下执行某项 Capability 的可识别人、团队、软件组件、AI 系统、服务、平台、workflow 或制度机制。

Qualification 是关系性的，而不是绝对的。一个语言模型可能适合在有人类复核时起草低风险备选方案，却不适合发布具有约束力的法律决定。一个支付服务可能只在特定货币、交易上限、司法辖区与可用性目标下合格。一个专家可能在熟悉领域中合格，却在知识时效、独立性、工作负荷或授权条件不满足时失去资格。因此，同一项 Capability 可以由多个合格的 Capability Unit 提供，同一个 Unit 也可以在不同 Context 中具有不同 Qualification。

NIST 的系统工程指南把 Assurance 定义为基于客观 Evidence、将不确定性降低到可接受水平而形成的 justified confidence，并要求工程活动的严谨程度与系统元素被赋予的信任相称。[S7] Hero 接受这一方向，但不把某一套工程认证方案扩展为普遍规则：对 Capability 的信心必须由与 Value Commitment 及其重大 Consequence 相称的 Evidence 加以证明。

胜任性、退化与过期

Capability 并不是一旦获得就永久存在。运行环境变化、Dependency 漂移、数据分布移动、接口改变、技能衰退、工作负荷超出限制、Authority 过期，或新 Evidence 揭示 Failure Mode，都可能导致 Fitness 退化。Qualification 也可以按设计到期，因为旧 Evidence 已不足以支持当前依赖。曾经合格的 Capability Unit 不应被永久推定为合格。

这一点首先是理论要求，而不是流程规定：每项 Qualification 都具有 Context 与时间边界。过去成功的 Evidence 只有在当前用途仍保持关键相似性时，才能提高信心。重大 Context 变化会削弱过去 Evidence 的继承效力，并可能要求限制、重新验证或撤销。Canon 006 可以进一步规定记录、复核周期与 Control；Canon 002 只建立为什么必须存在某种机制。

Capability 的可信度也受 Verification 限制。当结果生成成本很低、检查成本很高时，表面的 Capability 可能比可靠 Capability 增长得更快。如果评估者无法区分有效结果与有说服力的错误，反复生产就不构成有意义的 Repeatability。Verification 可以是直接检查、抽样、独立复核、约束测试、与下游 Outcome 对照，或由 Assurance Case 支持。方法可以变化，但依赖声明必须能够被挑战这一要求不变。

创意、探索与紧急 Capability

创意、探索与紧急工作不会使这一定义失效。它们可重复的单位通常不是相同 Output 或固定 Procedure，而可能是产生相关备选方案、进行有纪律的探索、在压力下作出可靠 Judgment，或在遵守约束的同时达到一类可接受 Outcome 的能力。Verification 可以检查推理质量、Provenance、约束满足、专家复核、获得的 Learning 或避免的 Consequence，而不必预先预测完全相同的答案。

边界仍然重要。一次成功如果不能为未来依赖提供合理依据，它只是一次 Achievement，还不是经过资格确认的 Capability。相反，只要 Judgment 过程与可接受结果类别能够被评估，无法预知精确 Output 并不意味着能力不可重复。Hero 的 Capability 概念必须足够宽，能够容纳人类专业能力与探索；也必须足够严格，能够区分负责任的依赖与希望。

必须建立的主张

  • Capability 不等于人、工具、任务、角色或一次性输出。
  • Capability Unit 是经过资格确认的 Capability 执行者。
  • 资格取决于适用条件、证据、限制与持续胜任性。

必须完成的论证

  • 定义结果、可重复性、验证、运行条件与资格确认。
  • 解释 Capability 如何退化、过期或失效。
  • 说明为什么同一个 Capability 可以由多个合格的 Capability Unit 实现。

必须回应的反例

创意、探索或紧急工作可能无法在狭义流程层面重复。

边界

可重复性可以指对某类结果或判断具有可靠性，而不是每次都使用完全相同的步骤或产生完全相同的输出。

可证伪检验

如果该定义排除了那些能够被负责任地依赖、但无法满足任何有意义的重复或验证条件的重要价值创造能力，就必须修订。

6. Capability Composition

核心观点组合能力扩大一个承担 Accountability 的人所能实现的范围，但组合本身会产生治理义务。

章节目的

解释规模如何扩大，同时避免把 scale 等同于 headcount 或无治理自动化。

理论正文

Capability Composition 是对两个或更多 Capability Unit 的有意安排，使其组合运行能够产生任何单一 Unit 不被期待独立产生的结果，或以更大的 Scale、Speed、Quality、Resilience 或 Reach 产生结果。组合可以包含人、团队、软件、AI、服务、平台、workflow、Control 与制度。它的力量来自专业化与协同；它的风险来自一个事实：整体行为不能仅由各部件的 Qualification 完整描述。

必须区分四种关系。Composition 是 Capability 与 Dependency 的整体安排；Orchestration 协调其中的顺序、信息、Decision 与 Handoff；Delegation 授权另一个主体或 Unit 执行有边界的工作或作出有边界的决定；Governance 建立选择、观察、约束、挑战、改变和停止该安排的依据。Orchestration 可以自动化，Delegation 可以宽也可以窄；只要组合可能对 Value Commitment 产生重大影响，Governance 就不可缺少。

组合会产生新的 Interface。每个 Interface 都可能转换信息、遗漏 Context、延迟 Signal、重新解释 Authority，或使完成状态产生歧义。组合也会产生 Dependency：一个合格 Unit 可能依赖其可见边界之外的身份服务、数据集、模型供应商、Operator、Network、Approval 或 Supplier。Failure 可以沿 Interface 传播，共享 Dependency 还可能使多个看似独立的 Unit 同时失效。因此，只有当 Failure Mode 足够独立且协调逻辑本身值得信任时，Redundancy 才会提高信心。

系统工程与安全研究为“部件级信心”提供了重要反证。NIST SP 800-160 指出，可信的系统行为不仅需要可信部件，还需要部件以可信方式相互作用，并把 Complexity、Dependency、Uncertainty、Verification 与系统级 Assurance 视为相互连接的问题。[S7] NASA 的 System Safety Handbook 同样要求整体性地看待系统及其组成部分的交互，指出复杂度增加可能超出传统部件级 Hazard 方法的识别能力，而 Scenario Analysis 必须处理 Interaction、Dependency 与 Combinatorial Effect。[S8] 这些来源并不能证明 Hero 的 Accountability 分配，但支持一个关键主张：合格部件不会自动形成合格组合。

Composition 的可信度

Composition Confidence 是对组合在目标 Context 中行为的有依据声明。它不能通过平均部件可信度或计算合格 Unit 数量得出，而受到重大 Dependency、Interface Uncertainty、Correlated Failure、Orchestration Logic、Observability 与 Intervention Ability 的限制。一个高度强大的组件，如果引入无法观察的关键依赖，或使系统运行超出 Hero 限制重大 Consequence 的能力，反而可能降低整体可信度。

只有当部件 Qualification 的 Evidence 与其在组合中承担的作用相关时，可信度才能被继承。Context 改变、Output 在 Verification 之前被转换、下游 Unit 把概率性输出当作事实、Control 与 Approval 集中于同一主体，或组合缺少可靠 Stop Path，都会削弱可信度。当重大行为来自 Interaction，而不是任何孤立部件时，必须存在系统级 Evidence。

下述八项治理条件在本 Canon 中不是实施清单，而是理论有效性条件。如果 Capability 未定义、Fitness 未证明、Authority 无边界、运行不可观察、Failure Propagation 未知、无法干预、重大决定缺乏独立检查，或 Qualification 无法撤销，那么 Hero 就没有合理基础为该 Composition 接受 Accountability。Canon 006 可以规定这些条件如何被记录和测试。

共享与不透明 Capability 中的 Accountability

Hero 对在 Value Commitment 中使用某个 Composition 承担 Accountability，但不会吸收所有位于其他边界内的 Accountability。共享 Capability 的 Owner 可以对其资格范围内的运行、Evidence、Limit 与 Change Communication 承担 Independent Accountability。Hero 可以依赖这项 Accountability，同时继续为 Selection、Context Fitness、Interface Design、Monitoring 与 Response 负责。明确分离的 Accountability 使 Scale 成为可能；模糊的共同责任则隐藏了挑战最终应由谁回答。

不透明并不自动意味着不合格。人们经常依赖无法完整检查的系统，也没有任何 Hero 能够理解复杂 Value Creation System 的每个内部机制。关键问题是：不透明是否由充分的外部 Evidence、有边界的 Permission、合同或制度 Assurance、独立评估、运行 Signal、Containment、Escalation 与 Replaceability 得到补偿。如果一项重大 Dependency 无法被观察、限制、挑战或替换，Hero 就不能把无知转换成信心。

这也回应了“复杂系统超出一个人的理解能力”这一反例。Hero Accountability 不要求一个人能够在头脑中完整模拟系统，而要求其作出 Judgment：建立适当 Governance、取得专业与独立 Assurance、承认现有 Evidence 的限制，并在 Composition 无法被负责任治理时拒绝、重新界定、暂停或升级 Commitment。只有当 Accountability Architecture 随 Capability Architecture 一同成长时，Scale 才是合法的。

必须建立的主张

  • 多项 Capability 可以组合成价值创造结构。
  • 组合会带来接口、依赖、故障传播与证据需求。
  • Hero 对为某项 Value Commitment 选择和治理的组合继续承担 Accountability。

必须完成的论证

  • 定义 composition、orchestration、delegation 与 governance。
  • 确定有效组合的最低条件。
  • 解释 Capability 的可信度如何在链路中被继承、限制或削弱。

已确认的 Capability Composition 治理基线

只有当 Hero 有合理依据去信任、观察、限制并改变用于 Value Commitment 的组合时，Capability Composition 才有效。

最低治理条件包括：

  • Capability Definition：明确预期结果与运行条件；
  • Qualification：每个 Capability Unit 都有 Evidence 证明其适用于目标 Context；
  • Scope and Authority：允许的决策、访问、数据、工具与行动具有明确边界；
  • Observability：Execution、Outcome Signal、Exception 与相关 Evidence 可以被检查；
  • Failure Boundaries：已知限制、依赖、重大 Failure Mode 与传播风险得到理解；
  • Escalation and Stop Conditions：当边界被突破时，Hero 可以暂停、替换、隔离或升级；
  • Separation of Duties：在同一主体不得同时产生和批准重大决策的场景中，存在独立检查；
  • Revalidation and Revocation：当 Context 或 Evidence 改变时，Qualification 可以过期、被挑战、被限制或撤销。

Hero 继续对 Composition 的选择、它是否适合 Value Commitment、接口治理以及对 Evidence 的响应承担 Accountability。负责某项共享 Capability 的人或制度，可以对该 Capability 在资格范围内的运行承担独立 Accountability。不同 Accountability 必须明确，而不能被合并成模糊的共同责任。

只有当外部 Evidence、限制、Control 与 Escalation Path 足以支持负责任治理时，才可以使用内部不透明的 Capability Unit。如果一项重大依赖无法被观察、限制、挑战或替换，该 Composition 就还没有充分的 Accountability 基础。

Composition 的可信度必须考虑最薄弱的重大依赖、共享依赖与相关性 Failure。增加更多 Capability Unit 不会自动增加可靠 Capability。

必须回应的反例

复杂系统可能超出任何一个人的直接理解与控制能力。

边界

承担 Accountability 不要求无所不知，而要求有依据的治理、升级机制、证据与对自身边界的承认。

可证伪检验

如果组合能力能够在完全没有 accountable selection、governance 或 escalation 的情况下，持续可靠地产生重大价值，该模型就必须修订。

11

7. Value Commitment

核心观点Value Commitment 把意图转化为一个可以被评估、并由人承担 Accountability 的承诺。

章节目的

定义连接人的 Accountability、Capability 与结果的核心承诺。

理论正文

只有当有人必须回答以下问题时，Intent 才真正具有运行意义：预期改善什么、为谁改善、在哪些边界内改善，以及如何评估这项主张。Value Commitment 就是完成这一转换的结构。它是对追求并评估一项合法实质改善所作的 accountable promise，不是对成功必然发生的预测，也不是声称不确定性已经消失。

这一区分同时保护雄心与诚实。如果 Commitment 意味着保证成功，那么只有琐碎或已知的工作才能被接受；如果它仅意味着真诚努力，那么任何 Failure 都可以通过活动数量得到辩解。Value Commitment 因此约束 Hero 在已接受边界内的 Judgment、Capability Governance、Evidence、Response 与 Learning 质量。它不会使 Hero 无所不能，也不会使所有 Outcome 都变得可控。

Value Intent 先于 Capability Architecture，因为“什么应该得到改善”必须治理“什么能够采取行动”的选择。如果从现有工具出发，再为工具寻找理由，这个顺序就被颠倒了。组织追求的将是 Capability Utilization，而不是 Value Creation；Success 也会被重新定义成所选工具恰好产生的东西。Commitment 提供判断依据，使 Capability 可以被选择、组合、限制、改变或拒绝。

Commitment 与相近概念

Value Commitment 与 Goal、Task、Requirement 和 Performance Target 相关，但不能相互替代。

  • Goal 描述期望方向或状态，但可能没有说明 Beneficiary、Legitimacy Basis、Accountability Center 或 Evaluation Logic；
  • Task 描述需要完成的工作，但不证明完成为什么重要；
  • Requirement 约束 Solution 或 Process 必须满足什么，但不一定表达完整 Value 主张；
  • Performance Target 规定一个可测阈值，但它可能只是某个 Indicator，甚至可以在没有预期 Outcome 的情况下达成；
  • Value Commitment 把 Purpose、Beneficiary、Material Improvement、Legitimacy、Economic or Resource Logic、Boundary、Accountability 与 Evidence 整合成一个可回答的主张。

Goal、Task、Requirement 与 Target 都可以位于一个 Value Commitment 之中，但不会自动成为 Value Commitment。一个团队可能完成所有 Task、达到所有局部 Target，而 Beneficiary 没有获得重大改善，或某个被外部化的主体承担了不可接受的 Consequence。

不确定性下的最低清晰度

Commitment 要求足以支持 answerability 的清晰度，而不是虚假的精确性。接受时，Hero 至少必须能够说明：

  1. 合法 Beneficiary 类别与预期 Material Improvement；
  2. 使该 Value 主张具有合法性的 Purpose 与制度基础；
  3. 使 Commitment 保持可持续的 Economic or Resource Logic；
  4. 当前可见的重大 Stakeholder、Constraint、Assumption 与可能的负面 Consequence；
  5. 人类 Primary Accountability Center 与相关 Independent Accountability Boundary；
  6. 可用 Authority、Resource、Decision Right、Access、Governance Support 与 Escalation Path；
  7. Baseline、Intended Outcome、Evaluation Horizon、Leading and Lagging Evidence，以及 Disconfirming Evidence；
  8. 必须拒绝、改变、暂停、升级或结束 Commitment 的条件。

这些要素在不同 Context 中不需要具有相同细节，其严谨程度应与 Uncertainty、Reversibility、Scale 与 Material Consequence 相称。英国 Magenta Book 同样把 Evaluation 视为应在 Intervention 实施前、实施中和实施后持续发挥作用的活动，并要求尽早检验 Intervention 如何工作、为什么可能失败、不确定性位于哪里、使用什么 Baseline，以及出现了哪些 Unintended Consequence。[S9] Hero 把它作为 Evaluation-aware Commitment 的支持性 Evidence，而不是照搬公共政策方法。

Discovery Commitment

Discovery Work 不是 Value Commitment 的例外，它只是改变了 Commitment 的对象。当 Solution 与最终 Value Path 都尚不可知时，Hero 可以承诺降低某项重大不确定性、检验某个因果 Assumption、识别可行的 Beneficiary Need，或决定是否应接受一项更大的 Commitment。

有效的 Discovery Commitment 必须说明：哪项不确定性重要、降低它为什么具有 Value、将收集什么 Evidence、哪些 Alternative 仍然开放、Discovery 将支持什么 Decision，以及在什么情况下继续探索不再合理。其 Outcome 可以是一个得到支持的方向、一个被拒绝的 Hypothesis、一个收窄的 Option Set，或者一个负责任的不继续决定。只产生研究 Artifact、却没有改变 Decision Basis，只是活动，不是已经完成的 Discovery Value。

这一边界避免两种相反 Failure。Premature Precision 会把未知工作强行写成虚假确定性；Unlimited Discovery 则让不确定性永久成为逃避 Accountability 的庇护所。即使无法承诺最终 Solution，Discovery Commitment 仍需对降低不确定性的质量与 Consequence 负责。

Authority、接受与改变

Authority 是 Commitment 接受基础的一部分。它不仅包含正式 Decision Right，也包含取得 Information、Resource、Capability、Governance Forum 与 Escalation 的实际能力。如果 Hero 缺少作出或影响范围内重大 Judgment 的手段，就不能负责任地接受对此的最终 answerability。

必要回应是拒绝、重新界定或升级。这条规则适用于接受之前，也适用于任何重大 Authority Gap 变得可见之时。后来发生且无法合理预见的 Authority 变化，不会反向证明原始接受不负责任；但它会形成一个新的 Decision Point。Hero 必须披露缺口，并寻求恢复 Authority、改变范围、转移、暂停或升级，而不能假装 Accountability Basis 没有变化。

因此，Commitment 是持久的，但不是不可改变的。当 Beneficiary、Context、Evidence、Authority、Risk、Capability、Economic Basis 或 Evaluation Horizon 发生重大变化时，Commitment 可以改变。重大改变要求重新进行 Judgment 并明确 Re-acceptance；否则组织会在执行一个新承诺的同时，仍用旧承诺进行评估。原始 Baseline、Rationale 与 Evidence 必须保持足够可见，以解释为什么改变。

Commitment 也可能相互冲突。两项合法 Commitment 可能竞争同一 Resource、产生不相容 Consequence，或受到不同 Independent Accountability Constraint 约束。仅仅宣布两者都是 Priority，并不能解决冲突。组织必须明确决定 Scope、Sequence、Resource、Authority 或 Higher-order Value，同时保留那些不能被合法交易的 Constraint。

当 Evaluation Basis 已经满足、Commitment 被明确替代、Horizon 或成立条件到期，或 Evidence 表明预期 Value 在已接受边界内不再合法或不可实现时，Commitment 应结束。拒绝与负责任终止都是有效的 Accountability Outcome。为了保持表面一致而继续一个已经失效的 Commitment，不是坚持，而是逃避 Judgment。

必须建立的主张

  • Value Intent 先于 Capability Architecture。
  • Value Commitment 指明受益对象类别、预期实质改善、合法性来源、经济或资源逻辑、相关利益方、约束与承担 Accountability 的 Hero。
  • Commitment 不是成功保证，而是对追求并评估明确价值所作的 accountable promise。

已确认的 Commitment-Authority Rule

Hero 不能一边接受 Value Commitment，一边在之后以 Authority 不足为理由逃避 Accountability。

在接受 Commitment 之前，Hero 必须判断现有决策权、访问权限、资源、治理支持与升级路径是否足以支撑负责任的判断。

如果条件不足，Hero 必须采取以下三种行动之一：

  1. 拒绝 Commitment；
  2. 重新界定其范围、Authority 或成立条件；
  3. 在接受之前，或在尚未解决的 Authority 缺口形成重大风险之前及时升级。

一旦接受 Value Commitment，已经知道或经过合理检查本应发现的 Authority 缺口，就不能成为免责理由。它说明该 Commitment 在缺少充分 Accountability 基础的情况下被接受。

已确认的 Evidence Commitment Rule

在接受 Value Commitment 时，必须说明足够的评估逻辑，以区分 Intended Value 与已经得到 Evidence 支持的 Value。理论上至少需要：

  • 相关 Baseline；
  • 预期 Outcome；
  • 可以显示可信进展的 Leading Evidence；
  • 可以验证实际 Value 的 Lagging Evidence；
  • 可能出现的负面或外部化 Consequence；
  • Evaluation Horizon；
  • 能够挑战或推翻 Value 主张的 Evidence。

Canon 002 定义这些要素为什么必要。Canon 006 可以在未来规定其正式表达方式与生命周期。

必须完成的论证

  • 定义价值需要清晰到什么程度，同时不假装不确定性可以消失。
  • 区分 commitment、goal、task、requirement 与 performance target。
  • 解释 commitment 如何变更、到期、冲突或被拒绝。

必须回应的反例

探索工作可能在价值或解决方案尚无法精确定义时就必须开始。

边界

Value Commitment 可以承诺降低不确定性或发现可行价值路径，但其证据与决策条件必须明确。

可证伪检验

如果 Value Commitment 在实践中无法与普通目标或分配任务区分，这个概念就没有成立。

8. Outcome、Evidence 与 Consequence

核心观点只有通过证据与重大后果解释结果，价值才具有可信度。

章节目的

避免 Hero 用输出数量、活动强度或有说服力的叙述代替价值。

理论正文

当多个不同对象被压缩成一个词时，Value Evaluation 就会失败。Output 是 Execution 产生的东西；Outcome 是 Beneficiary 或 System 的状态或行为变化；Value 是在考虑 Consequence 后，判断该 Outcome 构成合法重大改善；Evidence 支持或挑战这一 Judgment；Consequence 是 Commitment 产生的影响，无论它是预期还是非预期、正面还是负面、直接还是间接。

这些区别不仅是语言区别，也是因果区别。Output 可能促成 Outcome，但不能证明 Outcome；Outcome 可能出现，却并非由 Commitment 导致；Measured Change 可能使一个 Stakeholder 获益，却伤害另一个 Stakeholder；Persuasive Narrative 也可能在事后把它们连接起来，而缺少可靠 Evidence。因此，Hero 要求建立从 Action 到 Output、从 Output 到 Outcome、再从 Outcome 到 Value 的明确链路，并让 Assumption 与 Alternative Explanation 保持可见。

Magenta Book 也区分 Monitoring 或 Benefits Management 与 Evaluation。它把 Evaluation 描述为检查 Intervention 是否有效、如何以及为什么有效、产生了哪些额外或非预期影响、如果没有 Intervention 会发生什么，以及观察到的变化在多大程度上可以归因或关联到 Intervention。[S9] 这支持 Hero 的基本立场：Performance Monitoring 本身不能被当作 Verified Value。

Evidence 是一种关系

Evidence 不是某类天然具有权威性的 Document。同一份 Record 对一个 Claim 可能是强 Evidence，对另一个 Claim 可能是弱 Evidence，对第三个 Claim 可能完全无关。Evidence 存在于 Observation、Claim、Context 与 Judgment 的关系中。Provenance 说明 Observation 来自哪里；Relevance 解释它与 Claim 的关系；Reliability 说明它在多大程度上可信；Time Boundary 确定它适用于何时；Limitation 说明它不能证明什么；Challengeability 确保冲突数据与 Alternative Interpretation 仍然能够改变结论。

Evidence Sufficiency 也是关系性的。它取决于 Consequence 的重大程度、Causal Claim 的不确定性、Decision 的可逆性、错误成本，以及是否存在更强 Evidence。低风险且可逆的 Decision 可以在有限 Evidence 下负责任地进行；高影响或不可逆 Commitment 则要求更强的独立性、覆盖度、Reliability 与审查。Canon 002 不规定数值阈值，而是建立一项理论要求：Evidence Burden 必须随 Consequence Burden 上升。

任何单一 Measure 都不能被误认为完整 Value Claim。Quantity 可以隐藏 Quality，Average 可以隐藏 Distribution，Short Horizon 可以隐藏 Delayed Harm，而 Success Criterion 可能驱动行为去优化 Measure 而不是 Purpose。一旦 Indicator 成为强 Target，Actor 与 System 可能改善可见 Signal，却损害真实 Outcome。回应不是放弃 Measurement，而是保留 Causal Explanation，在重大场景中使用多种 Evidence，检查 Distribution 与 Negative Consequence，并确保 Disconfirming Evidence 在制度上仍然可能出现。

相互冲突的 Evidence 不能自动被当作 Noise 求平均。冲突可能揭示不同 Context、Stakeholder Experience、Time Period、Data-generation Method 或 Causal Mechanism。Hero 必须解释：冲突是否降低 Confidence、收窄 Claim、要求新 Evidence，或证明 Value 的分布并不均匀。无法承受可见 Counterevidence 的结论，不是 Evidence-based，而只是 Evidence-decorated。

因果、贡献与延迟 Outcome

Value 经常在 Execution 之后才出现，并受到多种 Cause 影响。Hero 不要求完美 Causal Attribution，但要求准确表达当前知道什么。当存在可信 Counterfactual 或 Comparison 时，Hero 可以提出更强的 Attribution Claim；当因果关系分散时，更诚实的主张可能是 Contribution：Commitment 通过有 Evidence 支持的 Mechanism 合理影响了 Outcome，但并非唯一 Cause。

在宣布 Success 之前，Causal Chain 应说明 Assumption、External Influence 与 Expected Time Lag。S9 的 Theory of Change 指南同样要求明确 Causal Chain、Actor、Affected Group、Required Condition、Assumption、Evidence Strength 与 Wider Context，并区分 Early or Medium-term Outcome 与 Long-term Impact。[S9]

Intended Value、Evidenced Progress、Provisional Value、Verified Value、Unresolved or Refuted 这些认知术语保护了时间维度。它们防止组织把 Intent 称为 Result，或把 Leading Indicator 当成最终验证。Leading Evidence 可以支持继续投资或提高对方向的信心；Lagging Evidence 才可能在以后证明 Intended Outcome 是否持续，以及 Delayed Consequence 是否改变原有结论。

只有当 Proxy Indicator 与 Intended Outcome 的关系得到解释并保持可挑战时，它才有效。Training Completion 可能只是 Exposure 的 Proxy，而不是 Changed Practice；Feature Use 可能只是 Engagement 的 Proxy，而不是 Beneficiary Improvement；Risk Control Installation 可能只是 Protection 的 Proxy，而不是 Loss 已经降低的证明。当 Proxy 改善、Intended Outcome 却停滞时，它是对原有 Causal Link 的反证，而不是把 Value 重新定义成 Proxy 的理由。

当 Evaluation Horizon 超出 Hero 的 Role、Tenure 或 Delivery Organization 时，Accountability 不会在 Handover 时消失。接受 Commitment 的 Hero 必须建立 Future Review Ownership，保留 Baseline 与 Evaluation Logic，转移相关 Evidence 与 Limitation，并确保未来 Judgment 仍能挑战原始 Claim。未来 Reviewer 可以承担新的 Evaluation Accountability；原始 Decision 仍然可追溯，而不是变成无主决定。

Material Consequence

Consequence 完成 Value Evaluation，因为 Benefit 与 Burden 很少只存在于 Intended Beneficiary 内部。Consequence 可以是 Intended 或 Unintended、Immediate 或 Delayed、Concentrated 或 Distributed、Reversible 或 Irreversible、Internalized 或 Externalized。如果一项 Commitment 通过把 Cost、Risk、Labor、Delay 或 Harm 移出测量边界来改善某项 Metric，那么局部 Outcome 的改善不能单独证明 Value。

Materiality 受到 Accepted Scope、Legitimate Authority、Reasonable Foreseeability、Practical Influence 与 Evaluation Horizon 的边界约束。这些边界防止无限 Accountability，但不能成为漏洞。Scope 不能被画得过窄，以至于已知 Affected Party 消失；Foreseeability 要求合理调查，而不只是 Hero 偶然看到了什么；Practical Influence 不只包括 Direct Control，也包括 Stop、Redesign、Disclosure 与 Escalation 的能力。

真正不可预见的 Event，以及由另一个明确 Independent Accountability Center 治理的 Decision，可以位于 Hero Final Answerability 之外。即使如此，Hero 仍需回答：Known Limit 是否被披露、Interface 是否得到治理、Evidence 是否被监测，以及 Boundary 变得可见时是否进行了 Escalation。Accountability 是在有边界不确定性下对 Responsible Judgment 负责，而不是事后拥有发生的一切。

一些重要 Outcome 始终只能被部分观察。在这些情况下，Hero 允许 Triangulation、Qualitative Evidence、Expert Judgment、Scenario、Contribution Analysis 与明确 Uncertainty；但不允许 Certainty Theater。正确结论可能仍然是 Provisional、Unresolved 或 Refuted。一个强迫所有重要 Value 都接受即时数值验证的框架，会系统性地偏好“可测量”而牺牲“真正重要”，从而无法通过自身的 Falsification Test。

必须建立的主张

  • Output、Outcome、Value、Evidence 与 Consequence 是不同概念。
  • Evidence 支持判断，但不能消除解释。
  • 后果包括预期、非预期、延迟、分布式以及被外部化的影响。

已确认的 Evidence 基线

Evidence 是具有可追溯来源，并能够支持或挑战以下判断的信息、观察或记录：某项 Value Commitment 是否产生了预期 Outcome、Material Consequence 或 Learning。

Evidence 必须有能力改变判断。如果某项信息无论显示什么都不会影响结论，它只是记录或装饰，而不是有意义的 Evidence。

Evidence 至少需要具备以下质量：

  • Provenance：它来自哪里，以及如何产生；
  • Relevance：它与 Value 主张有什么关系；
  • Reliability：该观察或记录在多大程度上可信；
  • Time Boundary：它代表哪个时间范围；
  • Limitations：它不能证明什么，以及可能存在什么偏差；
  • Challengeability：反证、冲突证据或其他解释是否能够改变判断。

一个 Indicator 不会仅仅因为可以测量就自动成为 Evidence。它与 Value 主张之间的关系必须被解释。Output Evidence 不能自动证明 Outcome 或 Value。

Evidence 支持判断，但不能替代判断。

已确认的 Delayed-Outcome 基线

当 Outcome 延迟出现或暂时无法直接观察时，Value 主张必须保留明确的认知状态：

  • Intended Value：存在价值意图，但尚无 Outcome Evidence；
  • Evidenced Progress：Evidence 支持当前方向，但预期 Outcome 尚未出现；
  • Provisional Value：已经出现初步 Outcome，但 Evaluation Horizon 尚未完成；
  • Verified Value：Evidence 已经满足预先声明的评估基础；
  • Unresolved or Refuted：Evidence 不足、相互冲突，或已经推翻 Value 主张。

这些术语用于说明当前究竟知道什么，并不是规定 HeroOS 的 workflow 或 lifecycle。

延迟出现的 Value 并不等于没有 Value，但在所需 Evidence 到达之前，它仍然是未经验证的 Value。

只有在与预期 Outcome 的关系和自身局限都被明确时，才可以使用 Proxy Indicator。Proxy 的改善不得被表述为 Value 已经得到验证。

Hero 不仅必须说明什么能够确认 Value，也必须说明什么能够推翻它。

已确认的 Material Consequence 基线

Material Consequence 是由某项 Value Commitment 引起或受到其显著影响，对人、组织或社会产生重大作用，并且处于 Hero 已接受的范围、合法 Authority、合理可预见性、实际影响能力与明确评估周期内的后果。

Hero 对负责任的判断承担 Accountability，而不是对无所不能承担责任。

Hero 仍然必须负责：

  • 定义 Value 及其边界；
  • 作出或组织重大价值判断；
  • 以合理审慎选择和治理 Capability；
  • 观察可获得的 Evidence；
  • 在风险或 Authority 超出已接受边界时停止、拒绝、重新界定或升级；
  • 对决策、已知取舍与产生的 Learning 作出解释。

Hero 不自动对真正无法预见的事件、明确超出已接受范围和实际影响能力的事项，或者由另一个明确的 Independent Accountability 中心治理的决策承担 Accountability。只有当 Hero 已经作出合理判断、披露已知限制并使用必要升级路径时，这些排除才成立。

必须完成的论证

  • 定义证据的质量、来源、相关性、及时性与充分性。
  • 解释结果延迟或部分不可观察时如何评估。
  • 回应指标冲突与 Goodhart 式测量失效。

必须回应的反例

某些高价值决策无法在决策者任期内得到验证，也无法建立直接因果归属。

边界

Hero 要求明确的 evidence logic，而不是完美测量或即时确定性。

可证伪检验

如果框架的证据要求系统性偏好短期可测输出，而牺牲重要的长期价值，就必须修订。

9. Learning 与 Organizational Memory

核心观点只有当证据改变未来判断、行为、记忆或能力时，学习才真正发生。

章节目的

解释为什么每次执行都应让组织更有能力，而不仅仅留下记录。

理论正文

Learning 是 Evidence 改变未来 Judgment、Behavior 或 Capability 所产生的变化。Information 可以被接收却没有被理解；Insight 可以发生却没有被保留；Lesson 可以被记录却从未被使用。因此，Hero 区分 Recording、Individual Learning、Organizational Learning 与 Organizational Memory。

Recording 保存 Information；Individual Learning 改变一个人的理解或行为；Organizational Learning 改变共享 Practice、Governance Choice、Capability 或 Decision Pattern；Organizational Memory 则使这种 Learning 在原始人员离开或遗忘之后，仍然可以被恢复并持续发挥作用。这四者可以同时发生，但任何一项都不能仅凭 Storage 推断出来。

NASA 的 Knowledge Policy for Programs and Projects 提供了一个有用的制度案例。它把 Capture、Retention、Utilization 与 Sharing 视为不同活动，把 Lessons Learned Information System 放在更广泛的 Knowledge Transfer、Development、Event 与 Tool 体系中，并要求把 Lesson 注入 Methodology、Standard、Training 与 Practice。[S10] 这并不能证明 Hero 的四部分定义，但支持一个重要区别：拥有 Repository 不等于改变 Organizational Operation。

从 Evidence 到 Memory

Organizational Memory 需要一条可追溯的转换：

Retained Evidence
+ Preserved Context
+ Explicit Judgment
+ Operational Change
= Organizational Memory

Retained Evidence 保留当时观察到什么，包括重大场景中的冲突或负面结果；Preserved Context 记录 Evidence 与 Judgment 相关时的条件，包括 Purpose、Stakeholder、Baseline、Authority、Capability、Assumption、Time、Constraint 与 Environment；Explicit Judgment 说明得出了什么结论，以及 Uncertainty、Alternative 与 Limitation；Operational Change 把结论嵌入组织未来会做什么，例如 Decision Rule、Capability Qualification、Design Principle、Control、Training Practice、Monitoring Question、Workflow、Tool 或 Escalation Condition。

这个公式不是 Database Schema，而是 Validity Test。没有 Context 的 Evidence 容易被错误应用；有 Context 与 Evidence、却没有 Judgment，会迫使未来每个使用者重新构造 Decision；没有 Evidence 的 Judgment 会变成 Unsupported Doctrine；前三者都有、却没有 Operational Change，只会形成一个允许组织重复同类错误的 Lesson Archive。

Memory 通过 Retention、Retrieval、Interpretation 与 Application 发挥作用。Retention 保持材料可用且真实；Retrieval 把相关材料带入未来 Decision；Interpretation 检查旧 Context 是否适合新 Context；Application 改变当前 Judgment 或 Action。任何一环失败都会破坏 Memory Function。无法找到的材料不是 Operational Memory；没有 Context 却被检索出来的材料，可能比已经遗忘的材料更危险。

因此，Context Fit 是强制要求。Learning 把 Context(n) 改变为 Context(n+1)，但得到的 Judgment 并不能普遍复用。在 Crisis 中、某项 Regulation 下、基于特定 Capability 或针对某类 Beneficiary 学到的 Practice，可能在其他环境中失效。Reuse 必须检查哪些 Causal Condition 仍然成立、哪些已经变化，以及新 Evidence 是否挑战旧结论。

Tacit Learning 与持久性

组织有时会改变 Behavior，却没有保留显式 Evidence。Routine、Story、Supervision、Culture 与 Skilled Imitation 都可以承载 Tacit Learning。当 Changed Behavior 可观察时，Hero 承认这是真实的 Organizational Learning，但不会自动称其为持久的 Organizational Memory。

Tacit Transmission 有自身优势：它可以保留难以形式化的 Judgment，并通过 Practice 进行适应；但它也很脆弱，可能随 Turnover 消失、在无法挑战的情况下变形、保留过时 Assumption，或成为没有人能够解释来源与边界的 Rule。在涉及重大 Consequence 时，组织应使足够的 Evidence、Context 与 Judgment 显式化，以支持 Challenge 与 Responsible Reuse。目的不是记录每个 Intuition，而是防止关键 Learning 依赖无法追溯的继承。

退出、替代与容量

Memory 不会仅仅因为持续存在就具有价值。一个能够学习、却不能取消已经失效学习的组织，会积累相互冲突的 Rule、过时 Assumption、有害 Bias 与过度 Retrieval Noise。因此，Organizational Memory 与 Admission Mechanism 一样需要 Exit Mechanism。

Active、Conditional、Retired or Superseded、Archived 与 Disposed 描述的是 Memory 与当前 Judgment 的不同关系，而不是 Canon 006 的 Lifecycle State。Active Memory 默认影响 Decision；Conditional Memory 仅在 Context 条件成立时适用；Retired or Superseded Memory 不再拥有当前 Decision Authority；Archived Evidence 继续用于 Audit、Research 或 Historical Reconstruction；Disposed Material 因 Law、Privacy、Security、Retention 或正当 Resource Constraint 被删除。

Records Management 提供了一个外部类比，但两者并不相同。NARA 指南区分到期后应销毁的 Temporary Record、必须永久保存并移交的 Permanent Record、已经被替代的 Authority，以及需要 Review 与 Update 的 Schedule；它还警告，“不再需要时销毁”这种模糊指令可能同时导致 Over-retention 与 Premature Destruction。[S11] Organizational Memory 比 Federal Records Management 更广，但这个案例支持明确的 Disposition、Authority、Review，以及当前使用与历史保存之间的分离。

只有当 Decision Influence 真正改变时，Retirement 才成立。一项被标记 Obsolete 的 Memory，如果仍然被 Default Search、AI Retrieval、Qualification Rule、Training、Control 或 Workflow 返回，它在实践中仍然 Active。Supersession 必须保留 Traceability，同时把当前 Judgment 指向新结论。Disposal 必须合法删除材料，但不能假装删除 Information 就证明组织已经取消了曾经嵌入的 Behavior。

容量限制作用于 Active Influence，而不是全部 History。在合法、安全、有用且成本合理时，Historical Evidence 可以大量存在；Active Memory 则会竞争 Organizational Attention，并可能产生 Contradiction、Delay 或 Automatic Bias。因此，正确目标是支持 Responsible Judgment 的最小充分 Active Set，而不是统一 Maximum Item Count。什么算充分，取决于 Domain Complexity、Consequence、Change Rate、Retrieval Quality，以及组织解决 Conflict 的能力。

每个 Active Memory Item 必须具有足够的 Ownership 与 Boundary，才能持续接受 Challenge：Applicable Context、Supporting Evidence、Explicit Judgment、Operational Effect、Effective Date、Review or Expiry Condition，以及 Known Dependency or Conflict。Canon 006 可以决定如何表达、复核、计数或自动化这些内容；Canon 002 只建立为什么没有 Ownership、Boundary 与 Exit 的 Memory 不能继续被信任。

当 Outcome 在 Hero 任期结束后才成熟时，Organizational Memory 负责把 Evaluation 延续下去。Baseline、Causal Assumption、Evidence Status、Limitation、Review Horizon 与 Future Owner 必须在 Handover 后继续存在。缺少这种连续性，Long-term Value 会在结构上变得无法验证，而组织则会因在 Consequence 出现之前宣布 Benefit 而获得奖励。

必须建立的主张

  • 被存储的信息不会自动成为 Organizational Memory。
  • 学习需要在未来行动、判断或可用能力中产生可观察变化。
  • Memory 必须保留证据，也必须保留解释证据所需的 Context。

已确认的 Organizational Memory 基线

Organizational Memory 是被保留的 Evidence、Context 与 Judgment，它们已经被嵌入未来的行为、治理或 Capability，使 Learning 不依赖某个人继续留在组织中。

Retained Evidence
+ Preserved Context
+ Explicit Judgment
+ Operational Change
= Organizational Memory
  • Evidence 记录当时观察到了什么。
  • Context 保留 Evidence 与 Judgment 成立时的条件。
  • Judgment 记录组织得出了什么结论，包括不确定性和被放弃的选项。
  • Operational Change 将 Learning 嵌入未来决策、规则、Capability qualification、workflow、control、tool、training 或 monitoring。

只有存储而没有 Operational Change 的内容，是 Archive 或 Knowledge Repository，而不是 Organizational Memory。缺少 Evidence 与 Context 支持的规则，是 Unsupported Rule。只存在某个人脑中的知识，是脆弱的 Tacit Knowledge，而不是组织级 Memory。

没有 Context 的 Memory，最终会变成组织迷信。

已确认的 Memory 退出与容量规则

一个能够学习的组织，也必须能够取消已经失效的学习。Organizational Memory 必须支持准入、按 Context 使用、复核、限制、替代、退出、归档与合法删除。

在概念上，Memory 可以处于：

  • Active Memory：当前并默认影响判断、治理或 Capability；
  • Conditional Memory：仅在明确 Context 条件成立时适用；
  • Retired or Superseded Memory：不得继续指导当前决策；
  • Archived Evidence：仅为审计、研究或历史追溯保留，不再拥有当前决策权；
  • Disposed Material：因隐私、法律、安全或保留规则要求而删除。

Memory 退出时，必须从实际决策影响中移除，包括默认 Search、AI Retrieval 与 Context、Decision Rule、Capability Qualification、Workflow、Control 和 Training。已经标记 Retired、但仍被当作当前内容检索的 Memory，实际上没有退出。

当 Context 改变、出现更强反证、相关 Capability 或法律变化、有效期结束、重复或冲突增加、产生有害偏见、Value Commitment 已结束，或合法保留规则要求删除时，Memory 应被复核、限制、替代、退出或删除。

Active Memory 应当是支持未来负责任判断所需的最小充分集合。Canon 002 不规定统一的项目数量，但要求每一项 Active Memory 都具有 Owner、适用 Context、支持性 Evidence、明确 Judgment、Operational Effect、生效日期、Review 或 Expiry Condition，以及已知依赖或冲突。

在合法且有用的前提下，历史 Evidence 可以大量保留。真正需要被限制的资源，是组织的主动注意力与当前决策影响。

没有退出机制的 Memory，最终会变成组织惯性。

必须完成的论证

  • 定义 retention、retrieval、interpretation 与 behavior change。
  • 解释过时或有害的 memory 如何被挑战与退役。

如果 Evaluation Horizon 超出 Hero 的岗位任期，Hero 仍然负责建立 Evidence 交接、后续 Review Owner 与继续评估所需的 Organizational Memory。

必须回应的反例

组织可能通过行为变化产生隐性学习，却没有保留显式证据。

边界

Organizational Memory 不要求每一条历史记录都保持 Active。它要求 Retained Evidence 与 Context、Explicit Judgment，以及被嵌入未来运行的改变之间存在可追溯关系。正式 lifecycle state、quota、retention period 与 automation 属于 Canon 006。

可证伪检验

如果有用的组织学习反复发生，却既没有保留证据，也没有改变行为、判断或能力，这一主张必须缩小。

10. Hero Model

核心观点Hero Model 描述完整的价值创造循环：Purpose、Responsibility、Capability、Value 与 Learning。

章节目的

推导五个要素之间的关系，同时避免把模型变成僵化工作流。

理论正文

Hero Model 是对 accountable value creation 的概念完整性检验。它检查五项必要功能是否存在：Purpose、Responsibility、Capability、Value 与 Learning。这些功能形成 Cycle，是因为每一项都会改变其他功能被解释的条件；但这个 Cycle 不是必须遵循的 Meeting、Phase 或 Handoff 顺序。

Hero Model 有意小于一套完整 Operating System。它不描述交付 Product、Service、Policy 或 Mission 所需的每项 Activity，而只识别最小概念功能，防止 Execution 与 Meaning、Human Obligation、Fitness、Consequence 和 Adaptation 脱离。

为什么五个要素不能相互替代

Purpose 建立什么重要以及为什么重要。它定义 Action 被判断时所依据的 Direction、Legitimate Beneficiary、Institutional Basis 与相关 Horizon。只有 Purpose、没有 Responsibility，仍然只是 Aspiration。它可以激发活动，却不能说明谁有义务行动或确保行动发生。

Responsibility 建立采取行动、执行、贡献或确保工作发生的 Duty。它可以在参与者之间分配、委派或共享。只有 Responsibility、没有 Capability，是缺少可信执行手段的义务。它可以制造压力，但压力不是 Execution Capacity。

Capability 使追求成为可能。它提供在明确条件下产生 Result 的合格能力，可以来自人、Software、AI、Service、Platform、Workflow 或 Institution。只有 Capability、没有 Value，是缺少合法检验的力量。它可以产生 Output、Scale 与 Efficiency，却同时远离 Purpose。

Value 在考虑 Evidence 与 Consequence 后，评估 Outcome 是否构成合法的重大改善。只有 Value、没有 Learning，会使 Evaluation 成为孤立结论。组织可能已经认识到 Success 或 Failure，却带着相同 Assumption、Qualification、Control 与 Blind Spot 进入下一项 Commitment。

Learning 改变未来 Judgment、Behavior、Capability、Governance 或 Context。只有 Learning、没有重新检验 Purpose，可能继续优化已经不再合法的昨日优先级。因此，Learning 只有在改变下一轮的起始条件时，才真正关闭本轮 Cycle。

没有任何要素是另一个要素的同义词。Purpose 不能执行，Responsibility 不能创造 Fitness，Capability 不能定义 Legitimacy，Value 不能自行保存，Learning 也不能永久决定什么应该重要。只有这些不同功能保持连接、又不被合并时，模型才完整。

贯穿 Cycle 的 Accountability

Accountability 不是第六个要素，因为它不是在 Learning 之后执行的另一项工作。它是有边界的 Final Answerability，治理 Hero 在完整 Cycle 中的 Judgment：如何解释 Purpose、如何组织 Responsibility、为什么认为 Capability 适用、如何评估 Value 与 Consequence，以及 Learning 改变了什么。

Responsibility 可以在系统中移动，而 Accountability 必须保持可追溯。Hero 可以委派 Execution、依赖 Independent Accountability 或使用 Shared Capability，而不必对每个局部 Action 承担 Responsibility；但在 Value Commitment 边界内，Hero 仍需为 Selection、Integration、Response to Evidence 与 Escalation 作出回答。因此，Accountability 是包围 Decision 的关系，而不是 Task List 中的一项 Task。

Context、反馈与非顺序工作

Context 包围 Hero Model，因为每个要素都会随条件改变含义。Purpose 依赖 Legitimate Beneficiary 与 Institution；Responsibility 依赖 Authority 与 Role Boundary；Capability 依赖 Operating Condition；Value 依赖 Baseline、Evidence、Time 与 Consequence；Learning 依赖哪些 Causal Condition 仍然有效。

这个关系可以表示为：

Purpose
↓
Responsibility
↓
Capability
↓
Value
↓
Learning

箭头表达 Dependency 与 Feedback，而不是强制 Chronology。真实工作可能从 Crisis、Available Capability、Unexpected Evidence、新的 Legal Constraint 或继承的 Organizational Memory 开始。Crisis 可能在 Purpose 完整表达前就产生 Immediate Responsibility；新 Capability 可能揭示过去不可能实现的 Value；Evidence 可能在 Planned Execution 完成之前就推翻 Commitment；Learning 也可能迫使组织重新考虑 Purpose，而不是简单开始下一次 Delivery Cycle。

在每种情况下，Hero Model 检查哪些功能已经存在、哪些仍然隐含，以及在工作可以负责任地继续之前，哪些功能必须变得可回答。Interruption、Iteration、Parallelism 与 Revision 因而都是模型的原生特征。Failure 不在于从“错误步骤”进入，而在于因为工作从其他位置开始，就让某个必要功能消失。

NASA Systems Engineering Handbook 为线性解释提供了一个有用反例。它把工程过程描述为贯穿 Lifecycle 的 Recursive 与 Iterative 活动，并区分“证明符合 Requirement”的 Verification，与“确认 Product 在目标 Environment 中服务 Intended Purpose 与 Stakeholder Expectation”的 Validation。[S12] Hero 不导入 NASA 的 Process Architecture，但这一差异加强了两个命题：概念 Cycle 不必是线性 Workflow；符合要求的 Output 也不等于已经验证的 Value。

Feedback 可以按不同速度发生。Immediate Evidence 可以在 Execution 中改变 Capability Use；Outcome Evidence 可以在 Delivery 后修订 Value Judgment；Long-horizon Consequence 可能更晚才改变 Organizational Memory。Hero Model 必须保持这些 Loop 连接，防止快速 Execution 跑在较慢 Evaluation 与 Learning 之前。

HERO 四原则继续作为公共记忆结构，帮助人们记住相关原则；但它不能替代 Hero Model，因为 Mnemonic 本身不会建立 Purpose、Responsibility、Capability、Value、Learning、Accountability 与 Context 之间的完整关系。两者承担不同功能，不应被强迫相互替代。

必须建立的主张

  • Purpose 定义什么重要。
  • Responsibility 建立人采取行动、履行职责或确保工作得以发生的义务。
  • Capability 使价值追求成为可能。
  • Value 评估这项追求是否真正重要。
  • Learning 改变下一轮循环。

Accountability 不是第六个顺序步骤，而是贯穿整个循环，对判断、价值与重大后果形成约束的最终回答关系。

必须完成的论证

  • 解释为什么五个要素不能相互替代。
  • 定义反馈以及 Context 的角色。
  • 说明模型如何容纳迭代、中断与修订。

已确认的 Context 基线

Context 是决定 Purpose、Responsibility、Capability、Value、Evidence、Consequence 与 Learning 如何被解释的条件集合。

Context 包括受益对象与 Stakeholder、Baseline、Authority 与 Accountability 边界、时间地点、资源条件、法律与伦理约束、风险、假设与不确定性、Capability 运行条件、Evidence 环境，以及相关历史 Judgment 或 Organizational Memory。

Context 不是第六个顺序步骤，而是包围完整 Hero Model 的跨周期解释边界。

Context(n)
    |
Hero Model Cycle
    |
Learning
    |
Context(n+1)

Learning 会改变下一轮判断发生的 Context。任何 Judgment 都不能脱离其 Evidence 产生时的 Context 被直接复用。因此，复用需要进行 Context-fit check，而不是简单重复历史结论。

必须回应的反例

真实工作很少按整洁顺序展开，也可能从证据、危机或现成 Capability 开始。

边界

Hero Model 是概念完整性检验，不是强制执行顺序。HERO 四原则仍是公共记忆结构，不替代 Hero Model。

可证伪检验

如果存在一类反复出现的 accountable value creation，其中必需的核心要素无法由五段循环或 Context 表达，模型就必须修订。

11. One Hero Team

核心观点One Hero Team 是一个承担 Accountability 的人类中心，由受治理的 Capability Unit 围绕。

章节目的

解释 Hero 最小可用的组织表达，同时不宣称传统团队已经过时。

理论正文

One Hero Team 是一种 Accountability Topology，而不是规定 Headcount、Reporting Line 或 Employment Model。它的定义中心，是一个人类对一项 Value Commitment 承担 Primary Accountability。围绕这个中心，是追求、评估并从该 Commitment 中学习所需的受治理 Capability。

One 指 Primary Accountability Center 可以被识别，不代表单方面权力或独自工作；Team 指对 Value Commitment 的协调参与，不只包括向 Hero 汇报的人。一个 Capability Unit 可以只参与一次 Decision、一个 Phase、一次 Execution，也可以参与多项 Commitment；它可以是内部或外部、人类或技术、专用或共享。

最小概念结构包括：

  • 具有 Legitimate Beneficiary、Boundary 与 Evaluation Basis 的 Value Commitment；
  • 一名在该边界内承担 Primary Accountability 的具名 Hero；
  • 为 Action、Performance、Review 与 Support 分布的 Responsibility；
  • 针对目标 Context 进行组合的合格 Capability Unit；
  • 明确的 Authority、Independent Accountability 与 Institutional Constraint；
  • Evidence、Escalation、Intervention 与 Stop Path；
  • 可以超越个人参与而持续存在的 Learning 与 Organizational Memory。

这是一种理论结构，而不是 Organization Template。传统 Product Team 可以满足它；Temporary Mission Group、Procurement Network、Public-private Program、Professional Case Team 或 Human-AI Arrangement 也可以满足。相反，一个成员稳定的 Department，如果无法识别 Value Commitment 与 Primary Accountability，也不构成 One Hero Team。

Participation 与 Governance

Team Membership 是 Capability Participation。相关问题不只是“谁属于这位 Manager”，而是“这项 Commitment 依赖哪些合格 Capability、在什么条件下依赖、具有怎样的 Responsibility、Authority、Evidence 与 Exit Path”。这一视角使 Shared Service、Specialist、Contractor、Platform 与 AI 变得可见，同时不假装它们具有相同法律或道德地位。

Qualification 证明为什么某个 Unit 可以在目标 Context 中被依赖；Delegation 分配有边界的 Work 或 Decision，而不让 Primary Accountability 消失；Coordination 治理 Unit 之间的 Sequence、Information、Interface 与 Conflict；Replacement 确保 Fitness 失效时 Unit 可以被限制或改变；Escalation 把 Team 连接到 Hero 边界之外的 Authority 与 Independent Accountability。

这些功能之所以必要，是因为 Capability Composition 改变了 Failure 的性质。强大的 Unit 可能被用于错误 Context，两个合格 Unit 可能交换不完整 Information，一个 Shared Service 可能同时使多个 Team 失效，而 Specialist 也可能发现一个 Hero 无权解决的 Constraint。因此，Team Governance 既治理个体 Performance，也治理 Relationship 与 Interface。

S12 把 System 定义为共同运行、产生所需 Capability 的 Element 组合，并指出超出各 Part 独立贡献的 System-level Value，主要由 Part 之间的 Relationship 创造；它也把 Multidisciplinary Integration 描述为把相互冲突的 Constraint 平衡成 Coherent Whole，而不是让单一 Discipline 支配整体。[S12] 这支持 One Hero Team 对受治理关系的重视，但 Hero 的 Accountability Model 仍然是独立理论主张。

Primary 与 Independent Accountability

一个 Primary Accountability 不意味着一个人作出所有 Decision。Safety、Security、Finance、Law、Professional Ethics、Democratic Authority、Audit 等领域可能要求具有独立 Decision Right、Approval、Veto 或 Duty 的 Independent Accountability。这些 Constraint 不是 Hero 可以优化掉的从属 Capability。

当每项 Accountability 都具有明确 Object 与 Boundary 时，结构仍然一致。Hero 为 Value Commitment 作答；Safety Authority 可以为已接受 Safety Constraint 作答；Data Custodian 可以为 Lawful Use 作答；Shared Capability Owner 可以为 Shared Service 的 Qualification 与 Operation 作答。这些中心发生 Conflict 时，需要授权的 Resolution Path；如果只宣布 Accountability 是 Shared、却没有边界，就没有任何中心能够可靠作答。

Primary Accountability 同样具有边界。Hero 不需要对 Shared Capability 在整个组织中的所有用途负责，而需要对在本 Commitment 中依赖它的 Decision、Context Fitness、Interface Governance，以及 Evidence 变化后的 Response 负责。Shared Capability Owner 则继续对该 Unit 被表示为合格时所依据的基础承担 Independent Accountability。

Scale 与 Value Creation System

Hero 中的 Scale，是通过受治理 Capability Composition 创造的 Accountable Value，而不是向 Manager 汇报的人数。增加 Headcount、Agent、Service、Automation 或 Parallel Work 会增加名义 Execution Capacity；只有当 Value Commitment、Interface、Evidence、Authority 与 Failure Boundary 仍然可治理时，才会增加 Legitimate Scale。

因此，One Hero Team 之上的单位是 Value Creation System：相关 Value Commitment、Hero Team、Capability Unit、Governance Boundary、Evidence 与 Organizational Memory 构成的网络。它的边界由 Value、Accountability、Capability Dependency 与 Consequence 决定，可以跨越多个 Department，也可以位于一个 Department 内部；可以临时存在，也可以长期存在。Reporting Hierarchy 无法单独定义它，因为 Hierarchy 未必跟随 Value 或 Failure 的流动。

Accountability 不会自动向上聚合。管理多名 Hero 的 Manager 不会自动成为所有 Commitment 的 Super Hero。只有当某个人接受一项独立的 System-level Value Commitment，拥有充分 Authority，并具有不能被局部 Commitment 替代的 Evaluation Basis 时，才存在 System-level Hero。该 System Accountability 负责协调和判断 System Value，但不会消除局部 Primary 与 Independent Accountability。

这种处理方式允许 System 嵌套和连接，而不要求组织中的所有 Consequence 最终都由一个人承担。它在每个已接受 Value Boundary 上保留可识别 Answerability，并要求在 Commitment 竞争、Dependency 跨边界或 Consequence 传播时建立明确 Governance。

必须建立的主张

  • 团队成员关系可以被理解为 Capability participation，而不仅是雇佣或汇报线。
  • 人类专家、AI agent、service、platform 与 workflow 都可能成为 Capability Unit。
  • Scale 是通过受治理的 Capability Composition 创造的 accountable value。
  • One Hero Team 由一个 Primary Accountability 中心、分布式 Responsibility、必要的独立制衡与明确的制度边界共同构成。

必须完成的论证

  • 解释 qualification、delegation、coordination、replacement 与 escalation。
  • 回应职责分离，以及必须由多个人分别承担不同 Accountability 的场景。

已确认的 Multi-Hero System 基线

One Hero Team 之上的单位是 Value Creation System：由相关 Value 组织起来的 Value Commitment、Hero Team、Capability Unit、Governance Boundary、Evidence 与 Organizational Memory 网络。

每个 Value Commitment 继续保留一个具名的人类 Primary Accountability 中心。Accountability 不会自动向上聚合成一个 “Super Hero”。

只有当某个人明确接受一项独立的系统级 Value Commitment，并拥有充分 Authority、Scope、Evidence 与 Governance Support 时，才存在系统级 Hero。该系统级 Accountability 不会消除系统内部已有的 Primary 或 Independent Accountability。

共享 Capability Unit 可以服务多个 Hero Team。维护共享 Capability 资格的 Accountability，与每个使用方 Hero 判断该 Capability 是否以及如何适用于具体 Value Commitment 的 Accountability，是两种不同责任。

Value Commitment 之间发生冲突时，必须存在明确的 Governance Mandate、Decision Right、Prioritization Basis 与 Escalation Path。不能仅依靠模糊 Shared Accountability 或汇报层级解决。

Value Creation System 可以嵌套或相互连接，但其边界应由 Value、Accountability、Capability Dependency 与 Consequence 决定，而不能默认等同于 Department。

必须回应的反例

安全关键、强监管、民主治理或高冲突领域，可能要求多个独立决策权。

边界

One Hero Team 不代表一个人拥有单方面权力、执行所有工作或替代制度治理。当范围与决策权明确时，同一个 Value Commitment 周围可以并存独立的 Accountability。

可证伪检验

如果该结构无法表达需要独立检查的领域，除非把 Accountability 重新变得模糊，就必须修订。

12. 从 Hero 到 HeroOS

核心观点当 Hero 原则需要在组织规模上变得可重复、可治理、可观察、可学习时，HeroOS 就被推导出来。

章节目的

展示从哲学到操作模型的推导，同时把正式要求保留给 Canon 006。

理论正文

Hero 首先是一套 accountable value creation 理论。当这套理论必须在重复 Commitment、多个人与 Institution、Composed Capability、长期 Evaluation Horizon、Turnover、Conflict 与组织规模中继续可靠成立时，它就变成一个 Operating-system Question。

在很小的规模上，Hero 原则可以通过非正式方式体现。一个人可以记住 Commitment、认识 Collaborator、检查工作、保留 Evidence，并把 Learning 带入未来。这是对“每种 Hero Practice 都需要具名 Platform、Ceremony 或 Formal Program”这一主张的有效反例。Informality 不会仅仅因为非正式就失效。

当 Answerability 开始依赖 Memory、Proximity、Stable Personnel 或 Exceptional Personal Discipline 时，限制就出现了。随着 Value Creation System 扩大，Capability 与 Accountability 跨越边界，Evidence 在 Handover 之后到达，Shared Unit 发生变化，Independent Constraint 发生冲突，旧 Learning 在新 Context 中被检索。此时，Repeatability 需要 Mechanism，使理论关系在直接参与者之外仍然可观察、可治理。

HeroOS 是这一 Operating-model Implication 的名称。它不一定是 Software，也绝不只是 Software。它可以包含 Social Practice、Institutional Authority、Governance、Record、Human Routine、Technical Tool、Interface 与 Automation。它的目的，是在这些关系无法仅靠非正式 Memory 可靠维持时，继续保存 Hero 理论所要求的关系。

推导必要功能

推导从 Failure Condition 开始：

  • 如果无法识别 Purpose 与 Value Commitment，Capability 可能在没有合法 Value Claim 的情况下被优化；
  • 如果无法识别 Primary 与 Independent Accountability，Delegation 与 Hierarchy 可能使 Answerability 消失；
  • 如果无法把 Authority 与 Scope 关联到 Commitment，Hero 可能接受一个无法负责任治理的 Promise；
  • 如果无法描述 Capability 与 Qualification，Access 可能被误认为 Fitness；
  • 如果无法观察 Composition、Interface 与 Failure Boundary，Scale 可能放大 Hidden Dependency 与 Correlated Failure；
  • 如果无法跨时间评估 Outcome、Evidence 与 Consequence，Output 可能被表述成 Value；
  • 如果 Learning 无法成为 Organizational Memory，System 将依赖个人保留并重复可预防 Failure；
  • 如果 Memory 无法被挑战与退出，过去 Learning 会变成当前 Inertia。

这些 Failure Condition 推导出 Commitment Identity、Accountability and Authority、Capability Qualification and Composition Governance、Evidence and Consequence Evaluation、Escalation and Intervention，以及 Organizational Memory 等概念功能。它们并不决定实现这些功能时使用的 Formal Role Name、Record Field、State Machine、Workflow、Threshold、Software 或 Conformance Test。

NASA Systems Engineering Handbook 提出了一个相关的功能性观察：无论这些功能由 Manager、Engineer、Internal Team 还是 Contractor 执行，Systems Engineering Function 都必须被完成，而 Formality 与 Documentation 应随 Type、Size 与 Complexity 调整。[S12] HeroOS 采用“必要功能、按比例实现”的原则，而不采用 NASA 的具体 Role 或 Process Set。

比例性与最小性

只有当 HeroOS 能在规模中保持 Answerability 与 Value 时，它才有正当性。更多 Process 不会自动带来更多 Governance。一个只产生 Record、不改善 Judgment，把 Authority 隐藏在 Ceremony 后面，延迟 Intervention，或使 Active Memory 过载的 Mechanism，反而会破坏它原本要实现的理论。

因此，理论要求是 Minimum Sufficient Operating Structure。结构必须足够强，使 Commitment、Accountability、Capability、Evidence、Consequence 与 Learning 保持可追溯和可挑战；也不应比 Context 与 Material Consequence 所要求的更复杂。Low-risk、Short-horizon Commitment 可能只需要很少显式结构；Regulated、Safety-critical、Long-horizon 或 Multi-institution Value Creation System 则可能需要更多。

Technology Agnosticism 由此产生。HeroOS 不能等同于 AI Platform、Workflow Product、Project-management Method、Organization Chart 或 Data Repository。它们都可能实现 Operating Model 的一部分，但没有任何一种能够仅凭 Brand 或 Installation 证明 Conformance。

为什么需要 Canon 006

Canon 002 只能证明某些 Function 与 Validity Condition 在理论上必要。如果不进一步规定组织如何识别 Role 与 Permission、表达 Commitment 与 Evidence、治理 Lifecycle 与 State Transition、管理 Interface 与 Escalation、控制 Access 与 Retention，并判断必要条件是否满足，HeroOS 就无法被检验。

这一 Specification Task 属于 Canon 006。只有 Canon 006 可以把理论描述转换成 Formal Requirement 与 Conformance Test。Canon 002 中 Intended Value、Verified Value、Active Memory、Qualification 或 Revocation 等术语，在 Canon 006 明确定义 Implementation Contract 之前，继续只是描述语言。

这一边界也保护 Experimentation。在 HeroOS 标准化之前，不同组织可以通过不同结构体现 Hero Theory，其实践可以为 Foundation 提供支持或反对 Evidence。不能因为某种 Implementation 看起来有用，就把 Canon 006 偷渡回 Canon 002。

如果非正式 Practice 可以在组织规模上可靠保存全部 Hero Relationship，而完全不需要任何 Repeatable Mechanism，那么这一推导就失败，HeroOS 这个名称也可能没有必要。但如果缺少 Durable Mechanism 时，Commitment、Accountability、Capability、Evidence、Consequence 与 Learning 会反复消失或变得模糊，那么 Operating Model 就不是可选项，只有它的 Implementation Form 仍然开放。

推导

如果价值需要一个可识别、承担 Accountability 的人，操作模型就需要识别 Hero 与 Value Commitment 的机制。

如果价值可以通过 Capability Composition 追求，操作模型就需要描述、确认资格、选择与治理 Capability 和 Capability Unit 的机制。

如果输出不足以证明价值，操作模型就需要 Outcome、Evidence 与 Consequence Evaluation。

如果执行应该改善组织，操作模型就需要 Learning 与 Organizational Memory。

这些需要推导出 HeroOS 的概念功能，但尚未规定角色、状态、仪式、schema、interface、control 或 conformance rule。

Canon 边界

Canon 002 可以定义这些功能为什么必要、彼此如何关联。Canon 006 必须定义正式运行要求与可检验的 conformance model。

已确认的 Canon 002 / Canon 006 边界

Canon 002 解释：为什么一套有效的 Hero 理论必须包含某个概念、关系、边界或必要条件。

Canon 006 规定：谁在什么时候，通过什么角色、权限、记录、状态、接口、Control、Threshold 或 Conformance Test 执行什么行动。

Canon 002 可以定义理论命题、概念关系、有效性的必要条件、反方观点、边界与可证伪检验。它可以规定 Capability 需要 Qualification、Composition 需要 Observability 与 Revocation、Value 需要 Evidence、Organizational Memory 需要退出机制。

Canon 006 必须定义正式角色与权限、必填字段与 Schema、Lifecycle 与 State Transition、Workflow 与 Approval、Escalation 与 Revocation Procedure、Retention Rule、Interface、Operational Metric、Threshold 与 Conformance Requirement。

只有 Canon 006 可以正式判断某个运行实现是否符合 HeroOS。Canon 002 中的 Active Memory、Verified Value 或 Intended Value 等术语是理论描述语言，不自动成为 HeroOS Lifecycle State。

Canon 002 必须保持技术无关，不规定具体组织头衔、软件平台、AI 产品或实现机制。

编辑判断是：

  • 如果一句话回答“为什么这是有效 Hero 理论的必要条件？”，它属于 Canon 002；
  • 如果回答“谁在什么时候，通过什么运行机制或 Control 做什么？”，它属于 Canon 006。

必须回应的反例

一个组织可能在没有安装或命名某种操作模型的情况下，非正式地体现 Hero 原则。

可证伪检验

如果 Hero 的主张可以在组织规模上成立，却完全不需要关于 commitment、capability governance、evidence、consequence 与 learning 的可重复机制，这一推导就不成立。

13. 限制、反方观点与可证伪性

核心观点只有当 Hero 的主张可以被界定、挑战与修订时，它才是一套理论。

这里所说的可证伪性

可证伪性比“允许批评”更严格。如果一套理论每次失败后都重新定义自己的术语，它就可以吸收无限批评。Hero 必须进一步说明：什么样的 Evidence 会使某项命题被保留、收窄、增加限定、替换或拒绝。

并非每一种 Hero 主张都以同一种方式接受检验。稀缺性转移假说这样的经验性主张，可以与成本、可获得性、生产率、失败和约束的实际变化比较。Value 经过验证需要 Evidence 这样的结构性主张，可以由反例挑战：如果某种结构能够持续产生有根据的评价，却不需要 Hero 所提出的关系，这一必要性主张就会减弱。以人为 Value 正当性中心这样的规范性主张，不能仅由生产率数据证明；它还必须接受伦理、法律、政治、制度推理与实际后果的检验。若不区分这些主张类型，看似精确的检验反而会造成误导。

因此，Canon 002 并不声称 S1-S12 已经证明 Hero。它们建立 Context、案例、反向 Evidence 或相邻学科依据。Hero 自有的理论关系仍然是需要独立比较、实地 Evidence 与专业审查的假说和论证。

适用范围限制

Hero 不是关于人、道德、政府、经济、意识或智能的普遍理论。它是一套有边界的理论，讨论在 Capability 可以被获取、组合、委派或自动化的条件下，如何进行有 Accountability 的 Value Creation。

当工作具有重大 Consequence、存在多种可能手段、Outcome 不确定，并且需要把 Judgment 与最终答责和 Learning 连接起来时，这套理论最为相关。如果行动是琐碎的、完全由规则预定的、没有实质后果的，或某个既有制度已经用不同名称保存同样的必要关系，Hero 可能不会增加太多价值。

采用 Hero 词汇并不能证明 Hero 有效。把 Product Owner、Manager、Professional、Public Official 或 Autonomous-agent Supervisor 改称 Hero，什么也没有证明。只有当这组组合命题能够解释既有模型无法同样充分解释的失败，或支持更好的 Judgment 时，Hero 才获得独特性。

反方观点 1 - Execution 仍可能是瓶颈

反方观点。 在许多领域，Intelligence-enabled Capability 并没有使 Execution 变得丰裕。物理劳动、受信任的关系、Tacit Expertise、监管批准、资本、基础设施、Attention、Coordination 与 Local Context 仍然可能稀缺。正如 S3 与 S4 的有边界 Evidence 所示，额外 AI 甚至可能拖慢处理高 Context 工作的资深实践者。

当前回应。 Hero 不要求 Execution 在所有地方都变得廉价。稀缺性转移假说主张的是：在某些 Context 中，相对约束会移动。随着某些 Execution 形式更容易获得，选择值得追求的 Value、接受有边界的 Accountability、治理 Capability Composition、评价 Consequence 与形成 Learning，会成为更显性的约束。S1 与 S2 支持这种可能性的部分内容；S3 与 S4 阻止它被写成普遍规律。

边界与不确定性。 这种转移可能不存在、只发生一部分、只是暂时出现，或者发生逆转。它也可能只出现在某个 Value Creation System 的一个阶段，而其他阶段继续受到 Execution 约束。

修订触发器。 如果跨相关领域的比较 Evidence 显示：Intelligence-enabled Capability 的可获得性提高，并没有实质改变约束位置、人类 Judgment 的分配或对 accountable selection 的需要，就应收窄或拒绝稀缺性转移命题。Hero 仍可能作为一套 Accountability 理论成立，但不能再以广泛的稀缺性转移作为理论基础。

反方观点 2 - Accountability 可以是集体或制度性的

反方观点。 复杂 Outcome 经常由集体产生和治理。Board、Court、Profession、Democratic Body、Incident Command、Partnership 与 Community 都可能作为制度合法答责。要求一个 Human Primary Accountability Center，可能过度简化共同因果关系、抹除独立职责、制造归责对象，或赋予某个人不应拥有的 Authority。

当前回应。 Hero 区分 Distributed Responsibility、针对有边界 Value Commitment 的 Primary Accountability，以及针对不同约束的 Independent Accountability。个人中心的目的，是防止最终答责消失，而不是宣称个人具有唯一因果关系、单方面 Authority 或拥有全部 Consequence。第 3 章与第 11 章明确保留了围绕主要中心的制度性和独立 Accountability。

边界与不确定性。 当前理论尚未证明，每一项合法的 Value Commitment 都能够或应该设置一个 Individual Primary Accountability Center。某些宪制、司法、科学、信托、合作制或民主 Decision，可能只有在最终答责真正保持复数时才有效。

修订触发器。 如果比较性制度 Evidence 表明：稳定的集体或制度结构能够在不制造无人负责 Commitment 的前提下，与个人中心同样好或更好地保存有边界的最终答责、Challengeability、Authority Alignment 与 Learning，就应以更广义的“可识别 Accountability”规则替代“单一人类中心”的要求。

反方观点 3 - 受治理的机器 Judgment 可能更可靠或更正当

反方观点。 Human Judgment 会受到偏见、不一致、疲劳、腐败与不可获得性的影响。受治理的机器系统可能在准确性、一致性、可审计性或平等待遇方面优于个人。在某些得到狭义授权的 Decision 中，Legitimacy 也可能来自法律、公共程序或制度设计，而不是由某个具体的人亲自判断。

当前回应。 Hero 并不把 Analysis、Recommendation、Optimization，甚至有边界的 Decision Execution 专属地保留给人类。它保留的是：在 Human Institution 内，针对重大 Consequence 的 Value Legitimacy 与最终答责。NIST AI RMF 支持 Human-centric Governance 与分布在 AI Actors 之间的 Responsibility，但没有证明 Hero 的具体分配方式。[S5] Reliability 与 Legitimacy 并不相同：更好的预测本身不能确定谁的利益应被计算、哪些伤害可以接受，以及系统出错时由谁最终答责。

边界与不确定性。 Human Review 可能只是仪式，Review 人员可能比机器更不了解情况，也可能根本无法改变 Outcome。如果一套理论只是把名义上的人插入自动化链条，它就不符合自身的 Accountability 标准。

修订触发器。 如果某种受治理的非人 Decision Arrangement 能够被证明具有 Legitimate Authority，能够参与 Challenge 与 Remedy，能够承担或可靠分配 Consequence，并且可以在没有 Human Accountability Center 的情况下持续形成 Answerability，就应收窄或替换 Human Primary Requirement。在此之前，机器性能优越支持更广泛的 Capability Delegation，而不支持 Human Institutional Accountability 消失。

反方观点 4 - Value 可能通过探索才逐渐出现

反方观点。 科学研究、设计、创业、诊断、探索、艺术与应急响应，经常在有价值的 Outcome 尚不可知时就必须开始。要求先定义 Value，可能奖励虚假确定性、压制发现，并把 Learning 错误地定义成失败。

当前回应。 Value Commitment 不必承诺一个预定 Solution 或已经验证的 Benefit。它可以承诺一个有边界的 Purpose、Beneficiary、Question、Learning Objective、Option Creation、Risk Reduction，或在明确不确定性下本身有价值的 Decision。第 7 章允许 Evidence 改变对 Value 的理解时修订 Commitment；它不允许在没有 accountable reason to continue 的情况下无限活动。

边界与不确定性。 某些探索在开始时甚至可能无法稳定界定 Beneficiary 或 Outcome Frame。事后的叙事也可能把没有 Purpose 的探索包装成有意创造的 Value。

修订触发器。 如果实地 Evidence 显示，即使只是 Provisional Pre-commitment 也会系统性破坏有价值的探索，就应为 Value Commitment Requirement 增加限定。如果开放探索在完全没有事先声明 Purpose、Beneficiary、Constraint 或 Learning Value 的情况下，仍能保持 Governable、Challengeable 与 Resource-justifiable，就应拒绝它作为普遍进入条件。

反方观点 5 - Evidence 可能延迟、政治化或不完整

反方观点。 Outcome 可能多年后才出现，Causality 可能高度分散，受影响的人可能彼此不同意，强势主体也可能控制测量内容。Evidence 可能制造虚假信心、偏袒可测量利益，或者到达得太晚，无法支撑有意义的 Accountability。

当前回应。 Hero 区分 Intended、Evidenced Progress、Provisional、Verified 以及 Unresolved or Refuted Value 语言。它要求 Provenance、Relevance、Reliability、Time Boundary、Limitations 与 Challengeability，同时承认 Contribution，而不是要求不可能的完整 Attribution Proof。S9 支持早期 Evaluation Design、不确定性、Counterfactual Reasoning、Unintended Consequence 与 Long-horizon Evaluation；它并不能消除政治 Judgment。

边界与不确定性。 更好的 Evidence Rule 不能使所有 Consequence 都变得可观察或中立。Evidence 本身也是在权力关系中选择的。有些重大价值部分是定性的、存在争议的，或无法压缩到共同 Measure。

修订触发器。 如果在某些明确领域，尽管经验 Evidence 长期不完整，透明 Judgment 与 Contestation 仍能维持有效 Accountability，就应收窄 Evidence Requirement。如果当前模型可预测地让可测量对象获得正当性，却排除重大但未测量的 Consequence，就应替换它。无法存在 Challengeable Evidence 时，应拒绝 Verified Value Claim；但不能把 Evidence 缺失自动转换成失败、成功或不存在的证明。

反方观点 6 - Capability Composition 可能破坏多于创造的 Value

反方观点。 每增加一个人、Agent、Service、Model、Supplier 或 Interface，都会增加 Dependency 与新的 Failure Path。Governance Cost、Security Exposure、Opacity、Coordination Load 与 Correlated Failure 可能比名义 Execution Capacity 增长得更快。

当前回应。 Hero 把 Composition 定义为受治理的 System Relationship，而不是简单聚合。Unit Qualification 并不充分；Interface、Observability、Revocation、Failure Propagation、Evidence 与 Proportional Governance 都很重要。[S7][S8][S12] 更大的 Composition 不会仅因为能够产生更多 Output 就变得更好。

边界与不确定性。 Foundation 没有提供一个普遍方法，预测 Composition 从何时开始产生净伤害。Governance 本身也可能成为瓶颈，或只是制造一种控制幻觉。

修订触发器。 如果在计入风险与 Governance Cost 后，更简单或更少治理的 Arrangement 持续优于 Governed Composition，就应收窄 Composition 命题。如果主导性的经验模式是不断增加且无法治理的 Consequence，而不是 Accountable Value，就应拒绝“Composability 是普遍优势”的想法。此时 Hero 必须把 Deliberate Non-composition 与 Capability Restraint 从例外提升为核心。

反方观点 7 - Learning 可以保持 Tacit

反方观点。 Team、Profession 与 Community 经常通过 Apprenticeship、Practice、Story、Habit 与 Shared Culture 学习，而不显式保留 Evidence。Formal Memory System 可能冻结过时 Judgment、降低 Psychological Safety、鼓励表演式 Documentation，或丢失 Expert 的 Tacit Knowledge。

当前回应。 Hero 不把 Organizational Memory 等同于 Repository。第 9 章要求 Evidence、Context、Judgment 与 Operational Change，因为 Storage 若没有改变行为就不充分。NASA Knowledge Policy 同样把 Capture 只视为 Cultivation、Transfer、Use 与 Infusion 的一部分。[S10] Tacit Practice 可以成为一种有效的 Memory Carrier。

边界与不确定性。 Explicit Traceability 并非总是可能或值得追求。在稳定、关系紧密的环境中，Tacit Memory 可能保持可靠；Formal Record 也可能主动造成误导。

修订触发器。 如果 Longitudinal Evidence 表明：组织可以在没有 Retained Evidence 或 Explicit Judgment 的情况下，保存 Challengeable Learning、把它跨越相关边界传递、使它适应变化后的 Context，并在过时时退出，就应扩展或替换四要素 Memory Test。如果 Tacit Mechanism 在其他环境中同样可靠，则应把 Organizational Memory Claim 收窄到高后果、高流动、分布式或存在争议的环境。

反方观点 8 - 现有模型或非正式实践可能已经充分

反方观点。 Product Management、Agile Delivery、Systems Engineering、Professional Ethics、Safety Practice、Evaluation、Records Governance、Public Administration 与 Institutional Law，已经在处理 Purpose、Responsibility、Execution、Evidence 与 Learning。管理良好的组织也可能非正式地体现全部 Hero Relationship。Hero 可能只是为既有实践提供了新词汇，而不是一套独立理论。

当前回应。 Hero 对独特性的主张更窄：在 Intelligence-enabled Execution 越来越容易获得的条件下，它把 Accountable Value Selection、Human Primary Accountability、Governed Capability Composition、Consequence-aware Evidence 与 Organizational Memory 组合起来。本版本使用的 Sources 表明，每一个相邻学科都提供必要概念；但没有任何 Source 能证明 Hero 的特定综合方式是必要的。

边界与不确定性。 如果综合能够澄清真实缺口，相似性本身不是弱点；但仅仅改名没有理论价值。Canon 002 尚未完成与最强版本既有模型的系统比较。

修订触发器。 如果既有模型单独或以已经存在的连贯组合，能够同样好或更好地解释相同失败模式、保存相同必要关系并指导 Judgment，而且不需要 Hero 特有概念，就应替换或拒绝 Hero 作为独立理论。如果非正式实践能够在组织规模上可靠维持这些完整关系，就应删除 HeroOS 的必要性推导。如果 Evidence 最多只支持 HERO 是一种有用的 Communication Framework，就只以这一较窄身份保留它。

理论层面的修订结果

当重大挑战得到支持时，Foundation 必须记录五种结果之一：

  • 保留（Retain）： 命题在已经声明的范围内经受住挑战。
  • 收窄（Narrow）： 命题只在更小的 Context 集合中继续可信。
  • 限定（Qualify）： 命题保留，但必须明确增加条件、例外或不确定性。
  • 替换（Replace）： 另一项命题能够更好解释 Evidence 与反例。
  • 拒绝（Reject）： 该命题不再值得留在理论中。

修订不能隐藏在“编辑澄清”之中。未来版本必须说明哪项命题发生改变、什么 Evidence 或推理引发改变，以及哪些下游章节需要重新考虑。

评估规则

Canon 002 必须用有边界的推理、比较性 Evidence 与可见的限制回应反方观点。如果 Evidence 不充分，正文必须把结论写成 Hypothesis 或 Research Question，而不是既定规律。一个反例可能只暴露适用范围限制，并不必然推翻整套理论；但如果一项主张可以不断适配、却没有任何可能被拒绝的条件，那么它就不具备可证伪性。

14. 研究议程与版本历史

核心观点Foundation 应公开尚未被证明的部分，使 Canon 可以增强，而不需要改写自己的历史。

研究原则

研究议程的目的，是让 Foundation 面临失败的可能，而不只是收集确认性案例。研究应保存不利案例、区分不同 Context、把 Hero 命题与可信替代解释比较，并报告不确定性。仅仅证明某种 Hero 实践“可以工作”并不充分；研究必须追问所提出的关系是否必要、是否独特，以及是否优于已有解释。

研究议程应组合实地案例、Longitudinal Observation、Comparative Institutional Analysis、适用时的 Controlled 或 Quasi-experimental Study、历史反例、Conceptual Analysis 与 Specialist Review。任何单一方法都无法同时解决经验性、结构性与规范性主张。

本章只在 Research Question 与 Disconfirmation 层面定义研究设计。正式 HeroOS Data Field、Workflow State、Evidence Schema、Threshold、Quota、Procedure 与 Conformance Test 继续属于 Canon 006。

研究计划 1 - 跨领域的稀缺性转移

假说。 当 Intelligence-enabled Capability 在某个 Context 中变得成本更低、更容易获得时，限制性工作会更多地从 Producing Output 转向 Selecting Value、Accepting Accountability、Governing Composition、Evaluating Consequence 与 Learning。

领域。 Knowledge Work、Software、Customer Operations、Science、Design、Physical Operations、Healthcare、Regulated Services、Public Administration、Education 与 Public-interest Work。

比较。 比较获得 Intelligence-enabled Capability 程度明显不同的相似工作；比较同一个 Value Creation System 的不同阶段；比较资深与新手实践者；比较 Capability 改变前后的时期。

所需 Evidence。 成本与可获得性变化、时间分配、Throughput 与 Quality、Failure 与 Rework、Coordination Load、Authority 与 Escalation Pattern、Outcome Evidence、Stakeholder Experience，以及尚未解决的约束位于何处。S1-S4 只是最初的有边界案例，不是跨领域结论。

否证结果。 如果 Capability Access 提高却没有改变 Constraint 或 Judgment 的分布，如果完整 System 的主导约束仍是 Execution Scarcity，或者 Governance 与 Verification Cost 吞噬了表面收益，该假说就会减弱。

所需审查学科。 Economics、Operations Research、Labor Studies、Domain Professionals、Human-computer Interaction、Organizational Psychology 与受影响劳动者代表。

研究计划 2 - Accountability Topology

假说。 当 Primary Accountability 可识别、Authority 已对齐或不足被升级，并且独立制度 Accountability 保持明确时，有边界的 Value Commitment 更可能维持最终答责。

领域。 Product Development、Safety-critical Operations、Clinical Care、Public Administration、Partnership、Board、Court、Scientific Collaboration、Regulated Profession、Cooperative 与 Crisis Response。

比较。 比较 Individual-primary、Genuinely Shared、Institutional、Rotating 与 Formally Unowned Arrangement。必须包含个人中心成为 Blame Target 或压倒合法复数 Authority 的案例。

所需 Evidence。 Decision Traceability、Challenge 与 Remedy、对 Insufficient Authority 的回应、Stakeholder Legitimacy、升级速度与质量、Consequence Allocation、Failure 后 Learning，以及跨人员变动的持续性。

否证结果。 如果 Collective 或 Institutional Structure 能够同样好或更好地保存 Final Answerability 与 Legitimacy，且不产生 Accountability Diffusion；或者 Individual-primary Structure 系统性扭曲复杂 Causation 与 Independent Duty，One-human-center 命题就会减弱。

所需审查学科。 Law、Political Theory、Corporate Governance、Public Administration、Professional Ethics、Safety Governance、Organizational Sociology 与受影响 Stakeholder 代表。

研究计划 3 - Evidence、延迟 Value 与争议性 Consequence

假说。 区分 Output、Outcome、Evidence、Value 与 Consequence，并明确 Provenance、Relevance、Reliability、Time Boundary、Limitations 与 Challengeability，可以改善 Judgment，同时不假装消除不确定性。

领域。 Preventive Health、Education、Climate 与 Infrastructure、Public Policy、Research、Brand 与 Trust、Risk Reduction、Social Program 与 Long-lived Commercial Product。

比较。 比较使用 Immediate Proxy Metric、Multi-horizon Evaluation、Qualitative 与 Quantitative Evidence、Contribution 与 Attribution Reasoning，以及 Stakeholder Contestation 的 Decision。必须包含 Measurement 导致 Goal Displacement 或排除重大利益的案例。

所需 Evidence。 Baseline、Causal 或 Contribution Argument、Unintended Effect、Benefit 与 Harm 的分布、随时间发生的修订、对 Evidence 的 Challenge，以及因后续信息而改变的 Decision。S9 提供 Evaluation Principle，但不能验证 Hero Evidence Model。

否证结果。 如果这些区分没有改善 Decision，反而制造不正当信心；或在 Evidence 结构性不完整的领域，透明的 Professional 或 Democratic Judgment 表现更好，该模型就会减弱。

所需审查学科。 Evaluation Science、Statistics、Causal Inference、Epistemology、Audit、Behavioral Science、Public Policy、Qualitative Research 与 Stakeholder 或 Community Review。

研究计划 4 - 跨人类与非人执行者的 Capability

假说。 Capability 可以通过有边界的 Condition、Repeatability、Verification、Qualification、Observability 与 Fitness for Purpose 进行 Technology-agnostic 定义，同时保留 Person、Organization、Machine、Service 与 Mixed Unit 之间的重要差异。

领域。 Expert Professional Work、Skilled Trade、AI-assisted Knowledge Work、Autonomous System、Shared Service、External Supplier、Team 与 Hybrid Human-machine Operation。

比较。 比较由不同 Executor Type 与 Composition 执行的等价 Function。研究可能抵抗稳定 Capability 描述的 Creative、Relational、Non-repeatable 与 Tacit Work。

所需 Evidence。 Performance Distribution、Boundary Condition、Context Dependence、Degradation、Recoverability、Handoff Quality、Qualification Validity、Human Effect 与 Failure Mode。Reliability 不能被当成唯一 Fitness Measure。

否证结果。 如果共同概念抹除了道德或运行上具有决定性的差异，无法表达 Non-repeatable Expertise，或者产生的 Qualification 在普通 Context 变化下失效，该概念就会减弱。

所需审查学科。 Systems Engineering、Human Factors、AI Assurance、Professional Education、Labor Studies、Cognitive Science、Safety、Accessibility 与 Domain Specialists。

研究计划 5 - Capability Composition、Failure Propagation 与 Governance Cost

假说。 只有当 Relationship Value 超过 Interface、Coordination、Assurance 与 Failure-propagation Cost，并且 Composition 能够按 Consequence 比例维持 Observable 与 Revocable 时，Composed Capability 才形成合法规模。

领域。 Software 与 AI System、Supply Chain、Healthcare Pathway、Public-service Ecosystem、Financial Operation、Emergency Response 与 Cross-organizational Program。

比较。 比较小型与大型 Composition、Centralized 与 Distributed Arrangement、Tightly 与 Loosely Coupled System，以及 Governed 与 Nominal Aggregation。必须包含成功的 Non-composition 与 Deliberate Simplification。

所需 Evidence。 Dependency Map、Interface Failure、Correlated Incident、Governance Effort、Security 与 Safety Exposure、Recovery Time、产生的 Value、Downstream Consequence，以及 Qualified Unit 组成 Unqualified System 的案例。S7、S8 与 S12 提供相邻的 System Reasoning，而不是 Hero 命题的证明。

否证结果。 如果所提出的 Governance Relationship 无法预测或降低重大 Failure，或者 Governance Cost 经常超过所保存的 Value，该命题就会减弱。如果简单 Arrangement 持续占优，Composition 必须成为更窄的例外。

所需审查学科。 Systems 与 Safety Engineering、Cybersecurity、Resilience、Operations Research、Complexity Science、Architecture、Supplier Governance 与 Frontline Operators。

研究计划 6 - Learning 与 Organizational Memory

假说。 当 Evidence、Context、Judgment 与 Operational Change 能够充分保留并影响未来行动，同时过时 Memory 能够通过 Review、Supersession、Retirement、Archival 或 Disposal 失去 Active Authority 时，Learning 才成为 Organizational Memory。

领域。 High-turnover Team、Professional Practice、Incident Learning、Long-lived Program、Public Institution、Regulated Operation、Research Organization 与 Community of Practice。

比较。 比较 Repository、Apprenticeship、Narrative Practice、Standard、Training、Embedded Control、Active-memory Limit 与 No-formal-memory Setting。必须包含 Over-retention、Forgotten Lesson、Stale Rule 与没有 Documentation 但具韧性的 Tacit Practice。

所需 Evidence。 在后续 Decision 中的复用、Context-fit Check、Behavioral Change、跨人员与边界的 Transfer、Challenge 与 Correction、过时 Judgment 的退出、Search 与 Maintenance Burden，以及可预防 Failure 是否再次发生。S10 与 S11 支持 Knowledge Use 与 Exit Concern，但不能证明四要素 Test。

否证结果。 如果 Tacit Learning 在相关 Context 中能够同样好地保存和更新 Organizational Judgment，如果 Explicit Evidence 没有改善未来行动，或者 Active Memory Control 造成的损失大于澄清，该 Test 就会减弱。

所需审查学科。 Knowledge Management、Records Governance、Organizational Learning、Anthropology、History、Information Science、Professional Education、Privacy 与 Legal Review。

研究计划 7 - 独特性与既有模型充分性

假说。 Hero 对 Purpose、Responsibility、Capability、Value、Learning、Accountability、Context、Value Commitment、Evidence、Consequence 与 Organizational Memory 的组合，能够解释一类既有模型或非正式 Practice 无法同样连贯处理的重大失败。

领域与比较对象。 Product Management、Agile 与 Lean Practice、Systems Engineering、Theory of Constraints、Socio-technical Systems、Professional Ethics、Safety Management、Evaluation、Organizational Learning、Public-value Theory、Governance、Institutional Design 与普通的 High-performing Team。

所需 Evidence。 Concept Mapping、与最强版本而不是弱实践的比较、Paired Case、Explanatory Coverage、Predictive Usefulness、Decision Quality、Adoption Cost、Vocabulary Burden，以及 Hero 不增加 Value 的案例。

否证结果。 如果一个既有模型或 Established Combination 能够以更少假设提供同样好或更好的解释与指导，就应替换 Hero 作为独立理论。如果非正式 Practice 能够在规模上可靠保存完整关系，HeroOS 就应失去其必要性主张。如果 HERO 只是一种有用 Mnemonic，则应相应收窄 Canon。

所需审查学科。 Organization Theory、Product 与 Agile Scholarship、Systems Thinking、Management History、Philosophy of Science、Institutional Economics、Public Administration，以及来自被比较传统的资深实践者。

整份 Foundation 的 Evidence 扩展议程

在进入出版审查之前，Foundation 需要比 S1-S12 更广的 Evidence Base。扩展应优先覆盖：

  • 关于 AI、Automation、Productivity、Work Design 与 Task Redistribution 的系统性和 Peer-reviewed Evidence；
  • 横跨 Law、Democratic Governance、Profession、Corporation、Safety 与 Collective Action 的 Accountability Theory；
  • Stakeholder Legitimacy、Public Value、Economic Sustainability 与 Distributional Consequence；
  • Capability、Competence、Expertise、Delegation、Automation 与 Human-machine Teaming；
  • System Composition、Complexity、Resilience、Security、Safety 与 Governance Cost；
  • Evaluation、Causal Inference、Measurement Politics、Delayed Outcome 与 Qualitative Evidence；
  • Organizational Learning、Tacit Knowledge、Records、Institutional Memory、Forgetting 与 Knowledge Retirement；
  • 与 Product、Agile、Lean、Systems、Institutional 与 Professional Model 最强版本的比较；
  • 不利与失败案例，尤其是 Hero-like Language 掩盖 Weak Authority、Blame Transfer、Surveillance、Bureaucracy 或 Unverified Value 的情况；
  • Non-English、Non-Western、Public-interest、Small-organization 与 Global South Context，用以检验理论是否嵌入了狭窄制度假设。

Evidence 扩展不能变成 Citation Accumulation。每个 Source 都必须说明它支持或挑战哪项 Proposition、其 Context 与 Limitation，以及它是否改变理论层面的信心。

专业审查议程

完整的 Foundation 不等于最终完成的多学科理论。持续审查至少应包括 Ethics、Law、Political 与 Institutional Theory、Economics、Organization Science、Product 与 Agile Practice、Systems 与 Safety Engineering、AI Governance 与 Human Factors、Evaluation 与 Causal Inference、Knowledge 与 Records Governance、Labor 与 Professional Practice、Public Administration，以及中英文双语编辑审查。

受影响 Stakeholder 不能由技术审查者替代。当某项命题为某个群体分配 Consequence 或定义 Value 时，该群体的代表必须能够挑战 Framing 与 Evidence。

版本原则

Version History 的目的，是保存理论的发展过程，包括 Correction 与 Rejection。

  • 英文继续作为 Source of Truth；中文必须保持同等 Claim Strength，不能静默解决英文中的 Ambiguity。
  • Version 必须区分 Editorial Change 与针对 Proposition、Scope、Definition、Relationship、Counterclaim 或 Revision Rule 的 Substantive Change。
  • Substantive Revision 必须说明触发它的 Evidence 或 Argument，以及被重新考虑的下游章节。
  • Earlier Version 必须保持可追溯；新版本不能重写旧主张，仿佛它从未存在。
  • Draft Completion、Theory Acceptance、Publication Authorization 与 HeroOS Conformance 是不同 Decision。
  • Canon 002 Versioning 记录 Theory Development，不定义 Canon 006 Implementation Workflow、Approval Role、Record Field、Lifecycle State 或 Release Control。
  • 任何 Version Label 都不能替代明确的 Publication Authority。

使用的 Evidence：达到 GPT-3.5 同等 MMLU 表现水平的 Inference Cost，从 2022 年 11 月每百万 Token 20 美元下降到 2024 年 10 月的 0.07 美元。这支持某一类 Intelligence-enabled Execution 的获取成本正在下降。

限制：Benchmark-equivalent Inference Cost 不等于成功的组织 Execution、已经实现的 Value 或物理稀缺性下降。

Source：Stanford AI Index 2025

S2 - Erik Brynjolfsson、Danielle Li 与 Lindsey R. Raymond, Generative AI at Work

使用的 Evidence：对 5,179 名 Customer-support Agent 的研究发现，每小时解决问题数量平均提高 14%，新手与较低技能人员提高 34%，而资深与高技能人员的变化很小。

限制：单一运行环境不能建立普遍 Productivity Effect，也不能证明 Execution 不再是瓶颈。

Source：NBER Working Paper 31161

S3 - METR, Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity

使用的 Evidence：随机研究报告，在熟悉 Repository 中工作的资深 Developer 获准使用 AI 工具后，完成任务反而多花费 19% 的时间。这支持额外 Capability 可能增加高 Context 工作执行时间的反方观点。

限制：METR 明确限制结果的推广范围，并在后来说明 2025 年初的结果已经不能代表当前工具。

Source：METR Early-2025 Developer Study

S4 - METR, We Are Changing Our Developer Productivity Experiment Design

使用的 Evidence：更新报告了参与者与任务选择效应、Concurrent-agent Measurement Difficulty 与更广泛的 AI Adoption。它支持 Context、Time Boundary 与 Measurement Humility。

限制：该更新没有给出一个可靠的单一 Productivity Estimate。

Source：METR Uplift Update

S5 - National Institute of Standards and Technology, AI Risk Management Framework 1.0

使用的 Evidence：该 Framework 把 Governance 视为 Cross-cutting Concern，并强调 Human Centricity、Social Responsibility、Sustainability、Context、预期与非预期影响，以及跨 AI Actor 的 Responsibility。

限制：它是一项自愿 Risk-management Framework，不能证明 Hero 的具体 Accountability Theory 正确。

Source：NIST AI RMF 1.0

S6 - Business Roundtable, Statement on the Purpose of a Corporation

使用的 Evidence：该声明同时讨论 Customer Value、Employee、Supplier、Community、Environment 与 Long-term Shareholder Value，支持商业系统中的多元 Stakeholder Value。

限制：它是一项自愿 Corporate Statement，不能解决 Stakeholder Conflict，也不能建立 Hero 的 Value Theory。

Source：Business Roundtable Statement

S7 - National Institute of Standards and Technology, Engineering Trustworthy Secure Systems

使用的 Evidence：NIST SP 800-160 Volume 1 Revision 1 以 Objective Evidence 建立 Assurance，并把 Complexity、Dependency、Uncertainty、Verification、Lifecycle 与 Compositional Trustworthiness 视为 System Concern。

限制：Systems-security Engineering Guidance 不能建立 Hero 的 Value Theory，也不能证明 Primary 与 Independent Accountability 的分配方式。

Source：NIST SP 800-160 Volume 1 Revision 1

S8 - NASA System Safety Handbook, Volume 1

使用的 Evidence：该 Handbook 以整体方式看待 System，并处理 Interaction、Dependency、Combinatorial Effect、Complexity、Scenario Analysis 与 Uncertainty，支持 System-level Failure-propagation Reasoning。

限制：NASA 的 Safety Method 与 Risk Tolerance 不能机械地迁移到每一个 Hero Context。

Source：NASA System Safety Handbook

S9 - HM Treasury and UK Government Analysis Function, Magenta Book

使用的 Evidence：该 Guidance 要求在实施之前、期间和之后开展 Evaluation，包括 Theory of Change、Baseline、Uncertainty、Failure、Unintended Consequence、Counterfactual、Contribution 或 Attribution，以及 Long-horizon Reasoning。

限制：英国 Public-policy Guidance 不定义 Hero Accountability，在其他 Context 中必须按比例调整。

Source：The Magenta Book

S10 - NASA Knowledge Policy for Programs and Projects

使用的 Evidence：该 Policy 区分 Cultivating、Identifying、Capturing、Retaining、Using 与 Sharing Knowledge，并要求把 Lesson 融入 Standard、Training、Methodology 与 Operation。

限制：NASA Policy 不能证明 Hero 的四要素 Organizational Memory Validity Test，也不能建立普遍 Memory Lifecycle。

Source：NASA NPD 7120.6A

S11 - US National Archives and Records Administration, Guide to Records Inventory, Scheduling, and Disposition

使用的 Evidence：该 Guidance 区分 Temporary 与 Permanent Record、Retention 与 Destruction、Superseded Authority 与 Schedule Review，支持明确的 Memory Exit 与 Review 区分。

限制：Records Management 不等于 Organizational Memory；改变 Decision Influence 与 Behavior 需要的不只是处置 Record。

Source：NARA Records Scheduling Guide

S12 - NASA Systems Engineering Handbook

使用的 Evidence：该 Handbook 通过 Element 与 Relationship 定义 System，描述 Recursive 与 Iterative Process，区分 Verification 与 Validation，并指出必要 Function 可以由不同 Role 以 Proportional Formality 执行。

限制：Technical Systems-engineering Guidance 不能建立 Hero 的 Value、Accountability、Team Topology 或 Organization Theory，也不能被转化为 HeroOS Process Specification。

Source：NASA Systems Engineering Handbook
