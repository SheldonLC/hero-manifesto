献词

献给那些在能力随手可得的时代，仍然选择承担责任的人。

03

创始人说明

Hero 起源于一个问题：

当智能变得丰裕之后，什么仍然是人类不可替代的价值？

答案不只是努力。

答案不是头衔。

答案也不是亲自完成每一项任务的能力。

答案是对价值的 Accountability。

Hero 写给 Founder、CEO、产品领导者、工程师、架构师、领域专家，以及每一个希望突破团队规模、层级结构和个人能力旧边界来创造价值的人。

Hero 不是对团队的否定。

Hero 是一种新的理解：当 Capability 可以被组合时，一个人可以成为什么。

04

Hero 宣言

我们相信，每个人都应该被赋能，在不放弃人的判断、目的与 Accountability 的前提下，创造超越个人能力边界的价值。

Hero 由 Accountability 定义， 而不是由头衔、权威或个人产出定义。

Capability 应该放大人的影响力， 而不是遮蔽谁对结果负责。

组织应该围绕价值和 Capability 来设计， 而不是被部门边界限制。

每一次执行都应该让组织变得更有能力， 而不是只交付一个结果，并让其中的学习消失。

HERO 四原则

这些信念共同构成 HERO 四原则：

H — 人的目的引领方向。
E — 扩展能力放大人的影响力。
R — 责任始终属于人。
O — 结果必须体现价值。

四原则说明 Hero 坚持什么。它们不是工作流程，也不替代 Hero Model。

05

第一部分：新时代

Key Idea: 智能正在变得丰裕。

在人类大部分组织历史中，执行能力都是稀缺的。

人必须被分组、管理、协调和排序，因为知识、劳动力和专业能力都存在于有限的人类能力之中。

团队建立在这种稀缺之上。

部门建立在这种稀缺之上。

许多管理系统也建立在这种稀缺之上。

现在，智能可以用新的方式被获取、组合和扩展。

软件可以执行。

AI 可以起草、推理、测试、搜索、设计、总结、编码、比较和监控。

平台可以协调过去需要多层人工交接的工作。

执行不再是同一种瓶颈。

这并不意味着人变得不重要。

这意味着人的重要性发生了位置迁移。

06

第二部分：真相

Key Idea: Accountability 成为新的稀缺。

当智能变得丰裕，最难的问题不再只是：

谁能完成工作？

更难的问题变成：

谁对价值负责？

谁解释什么才重要？

谁在模糊中决策？

谁在执行同时带来伤害与产出时接受后果？

谁从证据中学习，并改变下一次判断？

AI 可以执行工作。

AI 可以实现 Capability。

AI 可以产生证据。

AI 不能成为 Value Commitment 中承担 Accountability 的人类中心。

Capability 可以被委托。

Accountability 不可以。

07

第三部分：选择

Key Idea: 组织必须选择围绕结构，还是围绕价值。

旧结构从职位开始。

Hero 结构从价值开始。

旧结构问：

这属于哪个部门？

Hero 结构问：

哪个人接受这个 Value Commitment 的 Accountability？

旧结构问：

哪个团队有 capacity？

Hero 结构问：

需要哪些 Capability？在什么条件下？用什么证据验证？

旧结构衡量活动。

Hero 结构评估后果。

这不是要求消除层级。

这是要求我们不要把层级误认为价值创造。

08

第四部分：Hero

Key Idea: Hero 对价值负责，并被 Capability 放大。

Hero 不是头衔。

Hero 默认不是经理。

Hero 不是声音最大的贡献者。

Hero 不是 AI agent。

Hero 是一个可识别的人，他接受 Value Commitment 及其 material Consequences 的 Accountability。

Hero 可以使用人、软件、agent、workflow、platform、service 与 memory。

Hero 可以委托执行。

Hero 可以组合许多 Capability。

但 Hero 仍然对判断负责。

Hero 是目的、解释、证据与后果汇合的位置。

09

第五部分：One Hero Team

Key Idea: 团队不再只是人的集合。

在丰裕智能时代，一个承担 Accountability 的人，可以被许多 Capability Unit 围绕。

有些 Capability Unit 可以是人类专家。

有些可以是 AI agent。

有些可以是软件服务。

有些可以是 workflow 或 platform。

重点不是 AI 替代所有人。

重点是 Capability 变得可以组合。

One Hero Team 意味着：

Hero
Capability Units
AI
Platform
Service
Customer Value

这改变了 scale 的含义。

Scale 不再只是分配给一个团队的人数。

Scale 变成一个 Hero 通过受治理的 Capability Composition 能够创造多少 accountable value。

10

第六部分：Hero Promise

Key Idea: 每一次执行都应该让组织变得更有能力。

Hero 拒绝一次性执行。

工作不应该只产生输出。

工作应该产生证据。

证据应该产生学习。

学习应该改变判断、记忆或能力。

一个只执行而不学习的组织，会变忙，但不会变聪明。

Hero 组织把执行转化为 Organizational Memory。

它会变得更有能力，因为它以一种能改变未来行为的方式记住。

11

第七部分：关于 HeroOS

Key Idea: HeroOS 是让 Hero 可执行的操作模型。

Hero 是哲学。

HeroOS 是操作模型。

HeroOS 描述一个 Value Creation System 如何围绕以下内容组织：

  • Value Intent；
  • Hero Commitment；
  • Capability Architecture；
  • Execution；
  • Outcome Evaluation；
  • Organizational Learning；
  • Capability Evolution。

HeroOS 是技术无关的。

它可以包含 AI。

它可以包含软件。

它可以包含人类专家。

它也可以在传统团队仍然足够时包含传统团队。

HeroOS 不从工具开始。

它从价值、Accountability、Capability、证据和学习开始。

12

结尾宣言

未来不是没有人的世界。

未来不是工具承担责任的世界。

未来不是输出取代判断的世界。

未来属于那些接受 Accountability，并学会组合 Capability 的人。

这是丰裕智能时代。

这是 Hero 的时代。
