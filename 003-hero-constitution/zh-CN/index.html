01

序言

能力（Capability）可以由人、自动化系统或分布式结构提供。价值承诺（Value Commitment）的问责（Accountability）必须始终落实到可识别的人类判断与正当机构责任之上。

本宪章保护 Hero 接受、履行、挑战、移交或退出价值承诺的正当条件，并规定任何任务分配、多数决定、自动化、政策或紧急状态均不得消除的义务。

02

第一条 宪制地位

第一节 宪制功能

  1. 本宪章规定 Hero 以及依赖 Hero 的机构所应遵守的权利、义务、禁令和正当性边界。
  2. 本宪章依据 Canon 002 提出宪制主张，但不规定由 Canon 006 承担的运行控制。
  3. 任何机构都不得在表面上明确责任（Responsibility），同时扣留实现问责（Accountability）所必需的权限（Authority）、证据（Evidence）、挑战或补救（remedy）。

第二节 草稿状态

  1. 本文本是 Hero Canon 003 Founding Edition v1.0。
  2. 本文本是正式的 Hero Canon 出版物，但不是法律文书或 HeroOS 一致性规范。
  3. D3-1 至 D3-7 所记录的所有者决定、双语审查、边界审查和所有者明确批准，共同确立本 Founding Edition。

第三节 人类判断与机构责任

  1. 任务分配不构成接受。
  2. 能力（Capability）的委托不等于委托接受价值承诺（Value Commitment）所需的判断。
  3. 多数决定不会产生一个虚构的人类问责（Accountability）中心。
  4. 自动化不会消除可答责判断的必要性。
03

第二条 Hero 的权利

第一节 普遍性与比例原则

  1. 本条规定的权利属于每一位 Hero。
  2. 比例原则（proportionality）可以调整保护的形式、时点、独立程度和证据负担，但不得决定该项权利是否存在。
  3. 适用比例原则时，必须考虑重大后果（Consequence）、紧迫性、可逆性、可用证据（Evidence）、不确定性以及对受影响者造成的负担。
  4. 对后果较轻且容易恢复的决定，可以采用较轻的程序，但该项权利本身必须保持有效。

第二节 获得有边界价值承诺的权利

  1. Hero 在接受价值承诺（Value Commitment）之前，有权了解预期价值（Value）、正当受益者、范围、评估周期、重大约束、已知依赖和重大不确定性。
  2. 如果拟议承诺无法明确到足以支持负责任判断，就不得通过任务分配强加给 Hero。

第三节 获得充分权限或安全拒绝的权利

  1. Hero 有权获得与范围相匹配的权限（Authority）、访问相关证据（Evidence），并拥有可信的干预或升级路径。
  2. 充分权限不要求 Hero 单方面控制所有依赖，而是要求其拥有足以治理已接受范围的决策触达能力，并能在权限分散时使用可到达的升级路径。
  3. 缺少这些条件时，Hero 可以拒绝接受、请求重新界定范围或升级权限错配，且不得因此被认定为未履行一项尚未接受的承诺。

第四节 挑战与独立保护的权利

  1. Hero 可以挑战某项承诺的正当性、可行性、证据（Evidence）、后果（Consequence）假设、能力（Capability）组合或治理方式。
  2. 挑战是一项宪制功能，不得被视为不忠。
  3. 当决定对安全、法律、权利、受托义务、公共利益或其他受保护约束形成有可信依据的重大风险时，Hero 可以启动独立问责（Independent Accountability）。
  4. 被挑战的问责中心可以对复核提出异议，但不得控制是否存在真正独立的复核（review）。

第五节 获得补救与申诉的权利

  1. Hero 和任何受影响的利益相关方（stakeholder）都有权知道不利判断可以如何被纠正、暂停、复核（review）或申诉（appeal）。
  2. 申诉审查判断、证据（Evidence）、程序和责任归属，但不保证不可逆的后果（Consequence）能够被逆转（reversal）。
  3. 无法恢复原状时，补救（remedy）仍必须回应已经确认的伤害。

第六节 获得有边界问责的权利

  1. Hero 不对与某项承诺有关的一切事件承担无限责任。
  2. 问责（Accountability）的边界由已接受的价值承诺（Value Commitment）、正当权限（Authority）、可用证据（Evidence）、合理可预见性、实际影响力和声明的评估周期共同确定。
  3. 这些边界不能为隐瞒约束、可以避免却未作升级的失误，或 Hero 影响范围内的重大遗漏开脱。
04

第三条 接受、权限与判断

第一节 接受

  1. Hero 必须判断是否接受一项价值承诺（Value Commitment）。
  2. 接受是一项判断，不得从任务分配、沉默、系统归属、行政确认或持续承担运行托管中推定。
  3. 如果没有与范围相匹配的权限（Authority）、可信的安全拒绝路径或可到达的正当升级路径，任何 Hero 都不得接受会造成重大暴露的价值承诺。

第二节 负责任接受的条件

  1. 价值承诺（Value Commitment）必须明确到足以支持判断。
  2. 承诺至少应在概念上说明正当受益者、预期价值（Value）、重大利益相关方（stakeholder）、范围、权限（Authority）边界、重大约束、评估周期以及证据（Evidence）和挑战路径。
  3. 所需详细程度必须与重大后果（Consequence）和不确定性相称。

第三节 权限不足

  1. 接受之前，缺少充分权限（Authority）的 Hero 必须拒绝、请求重新界定承诺，或将错配升级给正当决策者。
  2. 接受之后，如果权限变得不足，Hero 必须寻求恢复权限、重新界定、升级、暂停、移交或退出。
  3. Hero 不得隐瞒权限缺口，也不得把原有问责（Accountability）基础描述为仍然完整。

第四节 拒绝、重新界定与退出

  1. 如果拟议承诺的价值（Value）不正当或在重大方面不连贯，其后果（Consequence）边界无法被理解到足以支持负责任判断，或权限（Authority）与能力（Capability）条件使接受无法成立，Hero 必须拒绝该承诺。
  2. 接受并不是不可撤销的继续履行承诺。
  3. 当新证据（Evidence）使预期价值失效、权限被撤回或超出、重大后果发生变化，或必要能力变得不适用时，Hero 必须寻求暂停、重新界定、移交、升级或退出。
  4. 退出必须说明理由，保护受影响的利益相关方（stakeholder），保存并移交重大证据与情境（Context），并处理剩余后果。

第五节 判断、证据与后果义务

  1. Hero 仍须对已接受承诺范围内选择、解释、排序、暂停或停止工作的重大判断承担问责（Accountability）。
  2. 委托执行不等于委托以下判断：某项能力（Capability）是否适用于其情境（Context），以及是否已经充分理解其重大依赖和失败边界。
  3. 重大价值（Value）和后果（Consequence）主张必须能够通过可追溯的证据（Evidence）、明确的限制和反证信号接受挑战。
  4. 后果状况发生重大变化时，会产生新的判断节点，并可能要求暂停、重新界定、升级、移交或退出。
05

第四条 紧急保护行动

第一节 紧急状态的成立条件

只有同时满足以下条件，紧急权限（emergency authority）才成立：

  1. 有可信依据的重大伤害正在发生，或防止该伤害的时效性机会正在消失；
  2. 可以合理判断，按通常程序等待会造成更大伤害；
  3. 拟采取的行动仅限于保护所必需的范围；以及
  4. 不存在可以合理获得、限制权利更少且同样及时的替代方案。

第二节 临时保护判断

  1. 无法及时触达通常权限（Authority）时，Hero 或最有实际能力防止重大伤害的另一名可识别人类，可以作出临时保护判断（temporary protective judgment）。
  2. 临时保护判断只允许采取即时保护所必需的行动。
  3. 它不会产生一般权限，不会设立新的价值承诺（Value Commitment），不构成接受，也不会取代机构问责（institutional Accountability）。

第三节 记录与复核

  1. 采取行动的人必须保存其判断、已知不确定性、已采取的行动和剩余风险。
  2. 该行动必须在实际可行的最早时间提交正当问责或独立复核（independent review）。
  3. 紧急期间被延后的任何保护义务，在即时危险解除后仍须履行。

说明性案例（非规范性）：现场工程师发现基础设施即将发生故障的可信迹象，而指定决策者无法取得联系。如果延误会造成更大伤害，工程师可以启动有边界的保护性停机。紧急状态不会授权其重新设计服务，也不会把永久责任转移给工程师。

第五条 移交与继任

第一节 重新接受

  1. 已接受的价值承诺（Value Commitment）可以通过有边界的继任继续存在。
  2. 问责（Accountability）不会仅凭任务分配而转移。
  3. 接任 Hero 必须根据当前范围、预期价值（Value）、权限（Authority）、证据（Evidence）、重大后果（Consequence）和评估周期重新作出接受判断。
  4. 在该判断作出之前，无论行政上的归属如何变化，该承诺都没有新的 Hero。

第二节 有效移交

只有同时满足以下条件，移交才生效：

  1. 当前价值承诺（Value Commitment）已经充分明确；
  2. 接任 Hero 明确接受该承诺；
  3. 已经具备与范围相匹配的权限（Authority）和实际干预能力；
  4. 重大证据（Evidence）、情境（Context）、已知限制和未解决的挑战已经移交；
  5. 受影响的利益相关方（stakeholder）在过渡期间得到保护；以及
  6. 剩余后果（Consequence）的答责安排已经得到明确处理。

有效移交不要求信息绝对完整，但重大不确定性和缺失信息必须保持可见。紧急保护性运行可以先于有效移交，但不会因此建立新的问责中心。

说明性案例（非规范性）：长期运行的支付平台在产品负责人离任后，仍可保持相同的预期价值。接任者仍须判断当前范围、合规暴露、权限、证据和评估周期。修改系统中的负责人字段不构成接受。

第三节 移交失败

  1. 如果没有接任 Hero 作出有效的接受判断，价值承诺（Value Commitment）就没有完成移交。
  2. 机构仍须对过渡条件和利益相关方（stakeholder）保护承担问责（Accountability）。
  3. 机构必须建立正当问责中心、重新界定承诺、暂停承诺或终止承诺。
  4. 运行托管只能为有边界的保护目的继续存在，不得被表述为已经接受并全面履行该承诺。

第四节 原 Hero 保留的答责义务

  1. 有效移交后，原 Hero 仍须对原接受判断、移交前的重大决定和遗漏、已披露限制与移交内容的完整性，以及其实际影响范围内的过渡义务承担答责。
  2. 原 Hero 不对新增范围、接任 Hero 后续作出的判断，或超出原评估周期、合理可预见性和实际影响范围的未来后果（Consequence）负责。

第五节 移交后的潜在伤害

  1. 如果移交后的可信伤害可能与移交前的判断、遗漏或披露失误存在重大关联，原 Hero 必须在合理可行范围内予以配合。
  2. 配合可以包括事实调查、解释原判断、披露相关证据（Evidence）及其限制、纠正记录，以及在当前实际影响范围内支持相称的补救（remedy）。
  3. 该义务不会恢复原 Hero 的运行权限（Authority），不会把当前问责（Accountability）转回原 Hero，也不会使其独自承担机构失误的全部责任。

第六条 证据、挑战、补救、申诉与学习

第一节 证据完整性与可复核性

  1. 紧急状态、保密要求、多数决定、政策、自动化或机构压力，都不能为伪造、重大篡改、销毁或隐瞒证据（Evidence）提供正当理由。
  2. 已知重大风险和重大不确定性必须得到保存，并在实际可行的最早时间向正当问责或独立复核（independent review）披露。
  3. 如果披露本身会增加重大伤害或违反受保护约束，可以限制即时披露或公开披露。
  4. 相关证据、延后披露的理由和复核（review）路径必须得到保存并可供复核。

第二节 正当挑战与资格

  1. 当利益相关方（stakeholder）的挑战对预期价值（Value）、证据（Evidence）、后果（Consequence）、权利、权限（Authority）、能力（Capability）、治理或补救（remedy）提出重大相关问题时，该挑战具有正当性。
  2. 挑战者受到该承诺影响，或提出重大相关知识或证据时，即具有提出挑战的资格（standing）。
  3. 挑战的正当性不取决于组织层级、是否同意 Hero、表达是否精致、是否使用首选渠道或是否已经提供完整证明。
  4. 机构可以管理无关重复、滥用或运行干扰，但不得以语气或对动机的怀疑为由，丢弃具有重大相关性的证据。

说明性案例（非规范性）：一名承包商以措辞欠佳的信息指出可信的安全控制失效。机构可以引导其使用可处理的渠道，但不得因为承包商的层级、身份、语气或未使用首选流程而丢弃该挑战。

第三节 最低回应

  1. 正当挑战必须得到保存。
  2. 挑战必须到达拥有充分权限（Authority）或可信升级路径的可识别回应者。
  3. 挑战者必须能够提交相关证据（Evidence）、获得免受报复的保护，并得到有理由的回应。
  4. 回应必须按比例提供独立复核（independent review）、申诉（appeal）或补救（remedy）路径。
  5. 回应的时点、深度和独立程度必须与重大后果（Consequence）、紧迫性和可逆性相称。
  6. 仅有自动确认，却没有权威触达、解释或干预路径，不构成有意义的回应。

第四节 强制独立复核

当正当挑战提出涉及以下事项且具有可信依据的重大问题时，必须启动独立复核（independent review）：

  1. 受保护约束；
  2. 不可逆或难以补救的后果（Consequence）；
  3. 主要问责中心的判断或利益冲突；
  4. 证据（Evidence）完整性、压制挑战或报复；或者
  5. 主要回应缺少充分权限或可信度。

复核必须具有足够独立性，能够审查争议判断并支持干预或补救（remedy）。如果名义上独立的复核者仍受被挑战决策者控制，该复核就不具有独立性。

第五节 证据不完整时的临时保护

  1. 有可信依据的重大伤害不要求等待完整证据（Evidence）后才开始相称的保护。
  2. 证据不完整本身，不得支持最终责任归属或不可逆的不利判断。
  3. 最低补救（minimum remedy）必须包括：明确不确定性、保存证据、采取限制权利最少且有效的临时保护、及时开展正当问责或独立复核（independent review），并根据后来确认的后果（Consequence）作出相称回应。

说明性案例（非规范性）：医院收到一项尚未完全核实的信号，显示某批药品可能受污染。医院可以隔离该批药品并保护患者，但不得仅凭初步信号对供应商或临床人员作出最终认定。后续证据必须导向解除隔离并纠正记录，或导向进一步补救。

第六节 申诉、逆转与回应性补救

  1. 申诉（appeal）复核判断，但不保证现实后果能够逆转（reversal）。
  2. 原有后果（Consequence）无法撤销时，问责（Accountability）仍要求如实说明、纠正记录、终止持续伤害、在可能范围内恢复原状、给予相称赔偿或正式承认，并采取措施防止再次发生。
  3. 只有复核（review）而没有回应性补救（responsive remedy），属于不完整的问责。

第七节 不得隐瞒重大伤害

  1. Hero 或机构不得向正当问责或独立复核（independent review）故意隐瞒已知重大伤害，或由可用证据（Evidence）支持、具有可信依据的重大伤害。
  2. 只有在即时披露会造成更大重大伤害或违反受保护约束时，才可以延后、限制或分阶段向受影响的利益相关方（stakeholder）或公众披露。
  3. 伤害、不确定性、延后披露的理由和复核（review）路径必须得到保存。
  4. 延后披露的正当理由不再存在时，延后必须终止。

第八节 学习与组织记忆

  1. 如果未来判断没有发生变化，补救（remedy）就是不完整的。
  2. Hero 和机构必须支持能够改变判断、行为、能力（Capability）、治理或组织记忆（Organizational Memory）的学习。
  3. 仅记录事件并不够。记录必须保存证据（Evidence）、情境（Context）、决策依据、限制以及后续行动所需的改变。
  4. 组织记忆不得长期依赖某一位前任 Hero 持续在场。
08

第七条 集体与机构问责

第一节 集体决策结构

  1. 集体决策主体（collective body）不会仅因共同作出决定或多数通过，就成为 Hero。
  2. 只有在其范围、正当权限（Authority）、决策边界、证据（Evidence）义务、后果（Consequence）责任和挑战路径均清晰可见时，集体决策主体才可以就明确的系统层级价值承诺（Value Commitment）承担机构问责中心的作用。
  3. 集体问责（collective Accountability）不得抹去作出重大判断的人，也不得把他们合并为虚构的“Super Hero”。
  4. 董事会、委员会、合伙组织或法律实体可以承担正当机构问责（institutional Accountability），其成员和管理人员仍须分别对自身判断和行动承担答责。

说明性案例（非规范性）：董事会可以对企业层级的价值承诺承担机构问责。“董事会决定”并不会抹去哪些成员提出、支持、反对某项决定，或未披露重大风险。管理层仍须对自身的执行判断承担答责。

第二节 机构剩余问责

  1. 无论是否存在有效的系统层级 Hero，机构仍须对只有自身才能创造、分配、保存或改变的条件承担机构剩余问责（institutional residual Accountability）。
  2. 这些条件包括治理结构、权限（Authority）设计、激励、资源和人员配置、能力（Capability）获取、证据（Evidence）与组织记忆（Organizational Memory）、挑战和补救（remedy）的可获得性、过渡保护，以及没有问责中心承接的重大剩余后果（Consequence）。
  3. 机构必须建立正当问责中心、重新界定承诺、暂停承诺或终止承诺。
  4. 没有 Hero，不等于没有问责（Accountability）。

第三节 结构性责任与个人过失

  1. 机构结构性责任（institutional structural responsibility）与个人过失（individual negligence）必须分别评估，也可以同时成立。
  2. 每一主体的答责范围，应当依据其能够正当控制或影响的重大条件、判断、行动和遗漏确定。
  3. 评估必须考虑权限（Authority）、可用证据（Evidence）、合理可预见性和现实替代方案。
  4. 结构性失误不能为伪造证据、压制重大警告，或在存在可信拒绝或升级路径时明知超越权限仍采取行动开脱。
  5. 个人过失不能免除机构对治理、激励、人员配置、权限或控制失误所承担的责任，只要这些失误对伤害产生了重大影响。
09

第八条 不可覆盖的限制

以下限制适用于紧急状态、多数决定、政策、自动化和机构压力下的所有情形：

  1. 正当复核（review）所需的证据（Evidence）不得被伪造、重大篡改、销毁或隐瞒。
  2. 正当挑战不得被删除，不得引发报复，也不得被阻止保存；一旦即时危险不再妨碍复核，必须及时提供独立复核（independent review）。
  3. 已知重大伤害或具有可信依据的重大伤害不得向正当复核故意隐瞒。
  4. 如果没有与范围相匹配的权限（Authority）、可信的安全拒绝路径或可到达的正当升级路径，任何 Hero 都不得接受会造成重大暴露的价值承诺（Value Commitment）。有边界的保护行动不构成接受。

比例原则（proportionality）可以调整时点、受众、渠道或保护形式，但不能取消这些限制。

第九条 与其他 Canon 的边界

第一节 Canon 002

  1. Canon 002 提供 Hero、价值承诺（Value Commitment）、问责（Accountability）、能力（Capability）、证据（Evidence）、后果（Consequence）、学习（Learning）和组织记忆（Organizational Memory）的理论基础。
  2. Canon 003 规定由该理论推导出的宪制权利和义务。
  3. 本宪章不修改 Canon 002 Founding Edition。

第二节 Canon 006

  1. Canon 006 可以规定正式角色、权限（permissions）、记录、模式（schemas）、生命周期状态、工作流（workflows）、阈值、接口、控制和一致性测试。
  2. 本宪章必须在不依赖这些实施细节的情况下保持完整、可理解。

第三节 Canon 000 与 Canon 001

  1. Canon 000 管理品牌与出版身份。
  2. Canon 001 陈述创始宣言。
  3. 两者都不能替代宪制治理。

第十条 解释与修订

第一节 解释

  1. 权利、义务与禁令必须结合解释。
  2. 拒绝、重新界定、升级、暂停、退出、移交、复核（review）、补救（remedy）、申诉（appeal）和逆转（reversal）是不同的宪制行为，不得以其中一项暗中替代另一项。
  3. 机构问责（institutional Accountability）与个人问责（individual Accountability）可以同时存在，任何一方都不得用于抹去另一方。
  4. 任何条款都不得依赖 Canon 006 的角色、字段、状态、阈值或工作流，才能表达其宪制含义。

第二节 原文与译本

  1. 英文文本是 Source of Truth。
  2. 简体中文文本是官方译本，必须保持相同的规范性力度（Claim Strength）。
  3. 规范性专有词汇必须在两个文本之间保持明确对应。

第三节 修订

  1. 每一项宪制主张都必须持续接受证据（Evidence）和正当挑战。
  2. 修订必须形成有理由的记录，并经过明确复核（review）。
  3. 任何宪制主张都不得通过静默编辑改变。
  4. 后续版本必须依据适用的出版标准获得所有者明确批准，并保留可见的版本历史。
